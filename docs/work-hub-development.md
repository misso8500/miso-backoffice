# 공동 업무 창구 단계별 개발

## WH-001: 업무 등록부터 공동 조회·수정·취소까지

목적: 카카오톡 지시와 개인 메모를 다시 취합하기 전에, 센터가 같은 업무 목록을 보며 담당자와 기한을 관리한다.

범위:

- 현재 Google 로그인 허용 계정을 공동 업무 구성원으로 연결한다. 최초 로그인 전에는 계정을 구분할 수 있는 이메일을 표시하고, 로그인 시 Google 이름을 반영한다. 기존 수급자 담당자 명부와 이름으로 자동 병합하지 않는다.
- 제목·상세·담당자·기한·센터 업무 분류·수급자/근로계약 관련자를 등록한다. 분류 미정과 담당자 미정도 허용한다.
- 요청자는 서버가 확인한 현재 계정이다. 담당자와 관련자는 다른 관계다. 근로자는 기존 계약 ID 기준으로 연결하고 주민등록번호로 새 업무 식별자를 만들지 않는다.
- API/DB 저장, 담당자별 조회, 수정·취소, 변경 이력, 동시 수정 충돌 방지, 실패 시 입력 보존.
- 관련자 간단 등록은 기존의 수급자/근로계약 초안 저장을 활용한다.

제외: 계획·수행, 주월 캘린더, 완료 판정, 일지/출근부/휴가서류 생성, 알림, 평가 지표 매핑. 이 단계에서는 존재하지 않는 기능의 메뉴를 만들지 않는다.

사용자가 **모두 조회·수정·취소 가능**으로 결정했다. 기존 로그인 허용 계정만 접근하고, 서버가 요청자·수정자를 기록한다. 직책별 승인 기능은 만들지 않는다.

완료 기준:

1. 인증되지 않은 요청은 업무 데이터에 접근할 수 없다.
2. 담당자·관련자의 존재와 입력값을 서버에서 검증한다.
3. 재조회/DB 재연결 후 등록·수정·취소 상태가 유지된다.
4. 다른 사람이 먼저 바꾼 이전 버전은 덮어쓰지 않고 409로 차단한다.
5. 업무와 변경 이벤트는 하나의 트랜잭션으로 저장한다.
6. SQLite 실제 HTTP 검사와 Postgres 저장 경계 검사, 기존 관련 검사 및 빌드 통과.
7. 사용 안내와 학습기록에 설계 이유·제약·검증 결과를 남긴다.

다음 티켓은 WH-002 일간 계획·수행, WH-003 주월 개괄, WH-004 업무일지 연결로 나눈다. 각 단계의 세부 범위는 앞 단계 사용 검토 후 확정한다.

## WH-001 구현 결과

공동 업무 메뉴, 기존 인증 계정 기반 구성원, 제목/담당자/기한/분류/관련자 등록·수정·취소와 이력 조회를 구현했다. 실제 명부 초안 생성도 기존 API를 재사용한다. 전체 92개 검사와 빌드를 통과했다. [사용 안내와 검증 한계](work-hub.md), [설계 학습기록](학습기록.md)을 함께 참고한다.

실제 운영 Postgres와 실제 로그인 브라우저 검토는 미실시다. 운영 DB는 이번 검증에 사용하지 않았다. 자동 커밋·배포·운영 데이터 생성은 하지 않았다.

## WH-001 보완: 고정 담당자 명부

사용자 지정에 따라 담당자는 신수연, 박준규, 황영상 순서로 고정한다. 로그인 계정 명부와 별도의 고정 담당자 테이블·참조 열을 추가해 기존 계정 배정을 보존한다. 요청자·수정자는 여전히 인증 계정이다. 역할은 화면에 표시하지 않는다. 담당자 선택/필터에 같은 순서를 적용하고 관련 검사 6개와 빌드를 통과했다.
