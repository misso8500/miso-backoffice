# 본인부담금 관리

수급자 → 본인부담금 관리에서 종합현황, 수납대장, 급여명세서, 영수증을 관리합니다.

## 사용 흐름

1. 종합현황 엑셀 가져오기에서 `.xlsx` 파일(최대 2MB)을 선택합니다.
2. 파일에서 읽은 청구 연월, 개별 금액, 원본 합계 차이, 수급자 명부 연결을 확인합니다. 동명이인은 직접 연결하고, 명부에 없는 사람은 미연결로 보관할 수 있습니다. 기초정보는 자동 생성하지 않습니다.
3. 확인 체크 후 저장합니다. 같은 월의 파일을 다시 가져오면 종합현황을 갱신하고 수납·가족요양 공제 기록은 유지합니다. 기존 수납 기록이 있는 사람이 빠지거나 연결이 달라지면 적용을 막습니다.
4. 수납대장에서 날짜, 월누계 수납액, 통장 여부, 납부자, 기타 항목, 가족요양 공제 내용을 입력하고 변경 전체 저장을 누릅니다. 공제는 설명만 기록하며 수납액에서 자동 차감하지 않습니다.
5. 문서 탭에서 기관 정보를 저장하고 명세서·영수증을 확인하거나 월별/선택 수급자별로 인쇄합니다. 수납완료 시에만 영수증에 수납일을 표시합니다. 직인과 간인은 24×24mm입니다.

## 저장과 조회

- 인증된 `/api/work/copay?month=YYYY-MM` GET/PUT 및 `/api/work/copay/import` POST를 사용합니다. 기존 로그인 허용 계정 정책을 따릅니다.
- 엑셀 전처리와 수급자 연결은 서버에서 검증합니다. 두 시트의 다른 열 배치는 머리글로 해석합니다. 이름 없는 금액 행은 제외 사실을 경고합니다.
- PostgreSQL과 SQLite 모두 `copay_months`의 월별 스냅샷과 `copay_events`의 변경 이력을 사용합니다. 스키마는 API 시작 시 생성됩니다. 기존 API 프로세스는 업데이트 후 재시작해야 합니다.
- 일괄 저장은 하나의 요청과 트랜잭션으로 처리합니다. 버전 충돌 시 덮어쓰지 않고 입력을 유지합니다. 새로고침으로 최신 자료를 확인한 뒤 재입력할 수 있습니다.
- 세부 탭 전환에는 추가 조회가 없습니다. 조회한 월을 메모리에 보관하고 저장 응답으로 갱신합니다. 최신 정보가 필요하면 새로고침을 사용합니다. 메뉴를 이동해도 미저장 입력을 유지하며 브라우저 새로고침·종료 시 경고합니다.
- 검토한 HTML 서식을 별도 프레임으로 격리해 기존 앱의 사이드바와 스타일, A4 인쇄 서식을 유지합니다. 실제 화면에서는 가명 샘플을 제거하고 서버 자료만 표시합니다. `copay-runtime.js`는 인증 요청을 상위 React 화면으로 위임합니다.
- 원본 파일의 바이너리는 저장하지 않고 파일명·해시·전처리 자료를 저장합니다. 직인은 앱에 포함된 제공 이미지입니다.

## 검증

`node --test tests/copay.test.mjs`는 시트별 열 위치, 읽기 전용 미리보기, 원자적 저장, 버전 충돌, 재임포트 보존, 월별 격리와 변경 이력을 검증합니다.

`tests/copay-ui.mjs`는 임시 SQLite와 인증 모의 서버로 실제 App 사이드바, 업로드, 날짜 입력, 메뉴 이동 후 입력 유지, 저장 후 재조회, 문서 확인을 데스크톱·모바일에서 검증합니다. `WORK_UI_PLAYWRIGHT_MODULE`로 Playwright 경로를 지정할 수 있습니다. 운영 데이터베이스는 테스트에서 수정하지 않습니다.
