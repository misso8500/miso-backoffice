# 본인부담금 디자인 검토

직인은 추가로 제공된 `tmp/직인_투명.png` 원본을 수정 없이 `assets/copay-company-seal.png`로 복사해 사용한다. 명세서·영수증의 직인과 영수증 중앙 간인 모두 같은 이미지로 가로·세로 24mm 고정 크기로 출력한다. 직인 칸과 중앙 간인 위치를 조정해 본문을 가리지 않도록 했으며 A4 한 장 출력은 유지한다.

브라우저에서 `copay-review.html`을 열어 확인한다. 외부 서버·라이브러리·네트워크 없이 동작하는 시안이다. 인영은 함께 제공되는 `assets/copay-company-seal.png`를 사용한다. 실제 업무 화면과 DB는 변경하지 않았다.

## 참조 파일 확인 결과

- `tmp/방문요양종합현황_202609.xlsx`: 2026년 9월, 2개 시트, 수급자 50행, 행 번호 중복 없음.
- 열: 수급자, 등급, 부담율, 월한도액, 급여사용액, 본인부담금, 초과/비급여, 합계, 납부총액, 미납/과납액, 납부일자.
- 제목·병합 머리글·반복 합계 행을 제외한 개별 행의 본인부담금 합계는 3,782,770원, 급여사용액은 41,704,700원이다.
- 원본 표기 합계는 각각 4,111,330원, 50,238,390원이다. 차이는 328,560원, 8,533,690원이며 원인 확인이 필요하다. 자동으로 어느 쪽에 맞춰 금액을 보정하지 않았다.
- 납부총액·납부일자는 50행 모두 공란이다. 공란은 ‘미등록’으로 표시한다. 0원 납부 대상자는 ‘납부대상 없음’으로 구분한다.
- 시안의 이름은 ‘수급자 01’ 등으로 바꿨다. `copay-source-demo.json`과 HTML에 실제 수급자명·식별번호·연락처를 포함하지 않는다. 금액은 참조 파일의 행 값을 유지한다.

## 화면 연결

1. 종합현황: 조회 전용. 월별 요약, 12행씩 목록, 검색·수납상태 필터와 문서 조회를 제공한다. 네 원형 아이콘은 각각 종합현황 입력(검정), 수납대장 입력(빨강), 급여명세서 확인(노랑), 영수증 확인(초록)을 나타낸다. 마우스·키보드 포커스 설명만 제공하며 클릭으로 상태를 바꿀 수 없다. 각 단계는 독립적으로 완료 여부를 표시한다.
2. 수납대장: 전체 50명에게 수납일·월누계 수납액·통장 여부·납부자·기타 항목·가족요양 공제대상·공제 내용 입력을 표시한다. 모달을 사용하지 않는다. 검색으로 숨겨진 행을 포함해 변경한 모든 행을 한 번에 검증·저장한다. 한 행에 오류가 있으면 아무 행도 저장하지 않는다. 입력 중 탭·월 이동은 미저장 변경 확인을 거친다. 월누계를 수정하는 방식이며 이전 입력은 내부 이력에서 취소 표시 후 대체한다. 무료 대상자는 0원 기록도 허용한다. 가족요양 정보만 저장할 수도 있고, 공제 금액·비율을 자동 산정하거나 수납액에서 임의로 차감하지 않는다.
3. 급여명세서: `tmp/본인부담금급여명세서_예시.png`의 장기요양급여비용 명세서 구조를 반영했다. 단일 12열 격자로 급여·비급여, 금액산정, 현금영수증·카드, 기관·직인을 정렬한다. 서로 다른 표의 폭이나 경계를 이어 붙이지 않는다. 미리보기와 출력은 190mm × 270mm를 기준으로 A4 인쇄 영역을 채운다. 본인부담금은 원본 값을 유지하고 공단부담금은 급여사용액에서 본인부담금을 뺀다. 상세 비급여 배분과 고유정보는 원천자료가 없으므로 공란이다. ‘명세서 확인’ 버튼이 노란 상태를 반영한다.
4. 영수증: `tmp/본인부담금영수증_예시.png`에 맞춰 센터보관용·수급자용을 나란히 출력한다. 한글 금액, 내용·금액·부담율·기타, 취급자·수납일·기관·직인을 고정 높이로 배치한다. 가족요양 공제대상의 공제 내용은 양쪽 보관본 모두 수령인 항목 바로 아래에 표시한다. 두 보관본의 경계에는 간인을 배치한다. 수납완료자에게만 실제 수납일을 표시한다. 부분수납·미등록자는 공란이며 미수납 상태임을 문구로 명시한다. ‘영수증 확인’ 버튼이 초록 상태를 반영한다.

`tmp/본인부담금수납대장_예시.png`에 맞춘 별도의 수납대장 출력도 제공한다. 연번·수납일자·성명·부담율·사용액 계·수납액·입금자·비고/공제를 고정 열 폭으로 배치하며 25명씩 A4 1쪽으로 나눈다. 수납일자는 YYYY.MM.DD 한 줄로 표시한다. 매 페이지에 소계, 마지막 페이지에 전체 총 수납금액 계와 통장·현금 합계를 표시한다. 입력 중 값은 합계에 포함하지 않는다. 예시의 ‘사용액 계’ 값이 원본 월한도액과 대응하므로 시안에서도 월한도액을 배치하고 이 매핑을 명시했다.

수납 기록을 변경하면 해당 수급자의 명세서·영수증 확인 상태를 해제해 다시 확인하도록 한다. 기관 공통정보나 인정번호를 변경해도 관련 확인 상태가 갱신된다. 인쇄나 단순 미리보기만으로 문서 확인 상태를 올리지 않는다.

## 임포트·서식 구현의 경계

참조 파일의 전처리 결과를 미리 넣었다. 파일 선택기는 검토 흐름을 보여주는 용도이며, 다른 파일을 실제로 파싱하거나 DB에 저장하지 않는다. 임포트 검토에서 합계 차이를 확인해야 시안 적용 버튼이 활성화된다. 재적용해도 이 시안에서 작성한 수납 기록은 보존한다.

실제 구현에서는 수급자 고유 ID 매칭, 동명이인 검토, 재임포트 차이 비교와 수납 기록 보존이 필요하다. 제공된 세 이미지의 표 구조를 HTML 출력 서식으로 재구성했다. 기관 고유정보와 수급자 인정번호는 문서 탭에서 입력하며 미입력 항목은 공란이다. 직인·간인은 제공된 영수증 이미지의 해당 영역을 SVG로 표시하고 적색 인영을 분리해 배치했다. 원본 이미지는 수정하지 않았으며, 다른 서명이나 직인을 새로 그리거나 추정하지 않았다.

## 검증

`tests/copay-prototype-ui.mjs`: PC·모바일에서 읽기 전용 원형 상태, 50개 행의 상시 입력, 전체 저장의 원자성, 가족요양 정보만 저장할 때 수납액이 생성되지 않음, 공제 내용의 수령인 아래 배치, 직인·간인 표시, 총수납금액, 날짜 한 줄 표시, 명세서의 A4 높이 충족을 검증한다. Chromium의 실제 PDF 생성 결과로 수납대장 50명=A4 2쪽, 명세서 2명=A4 2쪽, 영수증 1명·2보관본=A4 가로 1쪽을 확인했다. 실제 프린터 출력은 검증하지 않았다.
