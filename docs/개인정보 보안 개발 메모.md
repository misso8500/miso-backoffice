# 개인정보 보안 개발 메모

## 현재 판단

- 저장소 비공개 여부와 배포 사이트의 접근 통제는 별개다.
- 현재의 `백오피스 사용자` 선택 기능은 실제 인증이 아니다.
- 인증 없는 `/api/*` 요청으로 개인정보가 노출될 수 있으므로 실제 고객 데이터는 아직 입력하지 않는다.
- 보안 작업이 끝날 때까지 Vercel 배포 접근 제한을 유지한다.

## 다음 개발 우선순위

1. Supabase Auth 기반 실제 로그인 구현
2. 모든 API에서 access token 검증 및 미인증 요청 차단
3. 관리자·사회복지사 역할과 담당 수급자별 접근 권한 적용
4. 목록 API에서 주민등록번호 등 민감정보 제거
5. 상세 화면의 주민등록번호 기본 마스킹 및 저장 필요성 재검토
6. 민감정보 암호화와 복호화 권한 제한
7. 개인정보 조회·수정·삭제 감사 로그 기록
8. 최소 권한 DB 역할과 Supabase RLS 적용

## 운영 배포 조건

- 인증하지 않은 사용자는 모든 개인정보 API에서 `401`을 받는다.
- 권한이 없는 사용자는 `403`을 받는다.
- 수급자 목록 응답에는 전체 주민등록번호가 포함되지 않는다.
- 누가 언제 어떤 수급자 정보를 조회하거나 변경했는지 확인할 수 있다.
- `DATABASE_URL`과 비밀키는 Vercel 환경 변수로만 관리하고 Git에 포함하지 않는다.
- 위 조건을 검증하기 전에는 실제 개인정보를 저장하지 않는다.
