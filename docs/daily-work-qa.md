# 하루 할 일 QA 반영

## 구현

- 선택일 배치된 근무내역을 업무 등록·일반 업무 목록보다 위에 표시한다.
- 배치 건수, 배치 중 미수행 건수, 선택일 실제 수행 건수를 구분한다. 다른 날짜에 수행한 계획도 배치 중 미수행에서 제외한다.
- 계획은 보라, 수행은 초록, 기한 지난 업무는 주황 배경으로 구분한다.
- 오늘 계획의 `수행 저장`은 계획에 지정된 시간대로 즉시 저장한다. 시간대 미정은 미정으로 보존하며, 시간대별 수행 버튼과 수정·되돌리기도 유지한다.
- 일반 업무 완료 체크와 수행 저장의 의미를 유지한다. 수행을 저장해도 장기 업무 전체를 자동 완료하지 않는다.
- 기존 RFID 반복 규칙을 비활성화하고 미완료 생성 업무·계획을 취소한다. 완료 업무·실제 수행 기록은 보존한다. 실제 DB 정리는 변경된 서버의 context/tasks 조회 시 실행된다.

## 방문요양 서비스 연동 제안 — 생성 기준 확인 필요

현재 월별 수급자 선택은 서비스 대상 목록만 저장한다. 라운딩 방문완료는 업무와 수행 기록으로 연결되지만 RFID Check·급여제공계획서 등록·갱신 연락에는 생성 경로가 없다.

| 업무 | 제안하는 생성 근거 | 확인할 기준 |
| --- | --- | --- |
| RFID Check | 방문요양 서비스 관리에서 선택한 수급자·서비스 월 | 수급자별/담당자별 묶음, 일일/월간 주기, 담당자, 서비스 정지일 제외 |
| 급여제공계획서 등록 | 서비스 신규 시작 또는 계획의 신규·갱신 실행기간 | 등록 필요 시점과 마감일, 기존 등록 완료 판정, 담당자 |
| 갱신 연락 | 수급자의 인정기간 또는 기관 이용기간 종료 | 어떤 종료일을 기준으로 할지, 사전 연락 일수, 담당자 |

생성 시에는 원천 기록 ID·업무 종류·기준 기간을 유일 키로 사용해 재저장·새로고침 시 중복 생성을 막는다. 서비스 대상 해제·일시정지·기간 변경 시 미완료 업무를 어떻게 처리할지 정하고, 완료 이력은 보존한다. 기존 라운딩 업무와는 중복 생성하지 않는다.

## 추가 입력 단축 제안

여러 업무의 실제 수행을 한 번에 기록할 경우 선택 목록과 수행일·담당자·시간대를 한 곳에서 지정하고 저장하는 방식이 적합하다. 적용 전 선택 건수와 대상을 보여주고, 버전 충돌 시 실패한 항목만 남겨 재시도할 수 있어야 한다. 현재는 오늘 배치된 계획의 단건 수행을 한 번 클릭으로 저장하는 개선을 반영했다.
