# Drive 연결 점검

> 수급자 실제 서류 연결 기능이 추가되었습니다. [수급자 Drive 서류 연결](recipient-drive-documents.md)을 먼저 확인하세요. 아래는 초기 테스트 연결에 대한 기록입니다.

2026-10-15 서비스 계정으로 지정한 테스트 폴더의 PNG 이미지 3개를 읽는 데 성공했다. API 메타데이터에 driveId가 없는 일반 폴더이므로 이번 테스트 대상은 Workspace 공유 드라이브가 아닌 내 드라이브의 공유 폴더다. 두 종류 모두 지원하는 요청 옵션을 사용한다.

## 로컬 설정

`.env.local`에 서버 전용 설정을 추가했다.

- `GOOGLE_APPLICATION_CREDENTIALS`: 저장소 밖에 보관한 서비스 계정 JSON의 절대 경로
- `DRIVE_TEST_FOLDER_ID`: 조회를 허용한 테스트 폴더 ID

JSON 파일을 저장소로 복사하지 않았다. 키 내용이나 토큰을 로그에 출력하지 않는다. VITE_ 접두사를 사용하면 안 된다. 배포 서버에는 로컬 데스크톱 경로가 존재하지 않으므로 현재 설정을 그대로 배포할 수 없다. 배포 인증은 별도 준비가 필요하다.

## 사용

1. API를 재시작한다: `npm run api`.
2. 개발 화면이 실행되지 않았다면 다른 터미널에서 `npm run dev`.
3. 승인된 Google 계정으로 로그인한다.
4. 수급자 또는 근로계약 상세를 연다.
5. **Drive 연결 테스트 → 테스트 이미지 불러오기**를 누른다.
6. 썸네일을 눌러 확대하고 이전·다음 장 또는 방향키로 확인한다. Escape는 확대 화면만 닫는다.

테스트 이미지가 특정 사람의 서류로 등록되지는 않는다. 기존 이미지 선택 기능도 아직 브라우저 내 미리보기이며 Drive 업로드 기능이 아니다.

터미널에서 `npm run drive:check`를 실행하면 폴더의 지원 이미지 수와 각 파일의 형식·바이트 수만 출력한다. 테스트 폴더의 지원 이미지를 모두 읽으므로 작은 테스트 폴더에만 사용한다. 이 도구는 로컬 관리자용 연결 점검이며 앱 로그인 대신 서버 인증 파일을 사용한다.

## API와 접근 제한

- `GET /api/drive/test-files`: 지정 폴더 바로 아래 JPG·PNG·WebP 목록
- `GET /api/drive/test-files/:id/image`: 지정 폴더 바로 아래 이미지 원본

두 API는 기존 승인 사용자 인증 뒤에 실행된다. 파일 ID로 요청할 때마다 Drive 메타데이터의 부모 폴더와 휴지통 상태를 확인한다. 폴더 밖 파일·바로가기·SVG 등 다른 형식은 제공하지 않는다. 읽기 전용 OAuth 범위를 사용하고 쓰기 API는 지원하지 않는다. 파일별 20MB 제한, 외부 요청 시간 제한, no-store 응답 및 nosniff 헤더를 적용했다.

현재 썸네일은 원본을 인증된 API로 가져와 브라우저에서 축소 표시한다. 실제 대량 운영 전에 축소 이미지 전송, 지연 로딩, 배포 응답 크기 제한을 고려해야 한다. PDF와 하위 폴더 탐색은 아직 미구현이다.

## 다음 개발

사람별 폴더 연결, 문서 종류 분류, 인정 기간·계약별 파일 연결, 페이지 순서 저장이 남아 있다. 실제 개인 서류 전체 폴더로 전환하기 전에 이 연결과 배포 인증을 구현한다.

검증: 실제 테스트 폴더 이미지 3개 읽기 성공, Drive·로그인 단위 검사 11개 통과, 프로덕션 빌드 성공. 실제 브라우저 조작 검증은 하지 않았다.

## Vercel 인증 설정 추가

이제 서버는 `GOOGLE_SERVICE_ACCOUNT_JSON` 환경 변수로 서비스 계정 JSON을 직접 읽을 수 있다. JSON 환경 변수가 있으면 로컬 파일 경로보다 우선한다. 잘못된 JSON이면 로컬 경로로 우회하지 않고 오류로 종료한다.

1. Vercel 프로젝트 → Settings → Environment Variables에서 새 변수를 만든다.
2. 이름은 정확히 `GOOGLE_SERVICE_ACCOUNT_JSON`으로 입력한다.
3. 컴퓨터의 서비스 계정 JSON 파일을 텍스트 편집기로 열고 `{`부터 마지막 `}`까지 전체 내용을 값에 붙여넣는다. 파일 경로나 Drive 링크를 넣지 않는다. JSON 전체를 추가 따옴표로 감싸지 않고, private_key 안의 `\n` 표기는 원래대로 유지한다.
4. Sensitive를 켜고 Production을 선택한다. Preview에서도 꼭 필요할 때만 별도로 적용한다.
5. 로컬 데스크톱 경로를 값으로 넣은 `GOOGLE_APPLICATION_CREDENTIALS`는 Vercel에서 제거한다. 컴퓨터의 `.env.local` 경로 설정은 유지해도 된다.
6. `DRIVE_RECIPIENT_FOLDER_IDS` 등 폴더 승인 설정도 배포 환경에 등록한다.
7. 이 변경 코드가 포함되도록 재배포한다.

JSON 키 파일은 Git/public 폴더/공개 Drive에 올리지 않는다. 채팅이나 스크린샷에 내용이 나타나지 않게 한다. VITE_ 접두사 변수는 사용하지 않는다.

이 설정은 Drive 인증만 해결한다. 별도로 확인된 `/api/auth/config` 등 다단계 API 주소의 Vercel 404 문제는 라우팅 수정과 배포 후 검증이 필요하다. 비로그인 데이터 접근 차단, 승인 계정 로그인, 미승인 계정 차단을 확인한 뒤 사용자에게 링크를 공유한다.
