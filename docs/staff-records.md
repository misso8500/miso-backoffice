# 사회복지사 근무기록과 서류

## 화면과 작성 순서

메인 메뉴의 **근무기록** 아래에 출근부·업무수행일지·연차대장을 추가했다. 먼저 센터 담당자 명부에서 작성 대상 직원을 직접 선택한다. 구글 계정은 접속 인증에만 사용하며, 허용된 계정은 여러 직원의 기록을 작성할 수 있다. 같은 직원을 선택하면 다른 계정에서도 동일한 기록을 이어서 관리한다. 직원별 서류 성명·직위·기관·기본 출퇴근·인정시간은 처음 한 번 등록한다. 저장하지 않은 내용이 있으면 직원 전환 전에 확인한다.

1. 공동업무의 실제 수행에 수행일·처리자·오전/오후를 기록한다. 업무 전체 완료 체크만으로 출근이나 수행을 확정하지 않는다.
2. 출근부에서 월을 선택하고 **월 출근부 자동 작성**을 한 번 누른다. 최신 근거와 확정 연차를 조회하여 확인 필요 날짜에 평일 기본근무·주말 휴무·연차 초안을 채우고 바로 저장한다. 이미 입력한 날짜는 유지한다. 실제 수행은 근거로만 표시하며 공휴일·실제 출근은 직접 확인한다.
3. 월 전체 표에서 근태·출퇴근·인정시간·연차 일수·비고를 바로 정정한다. 서명 입력 대신 작성 필요·검토 대기·검토 완료 상태를 색상과 글자로 표시한다. **이달 확정** 시 검토 완료가 되며 이후 내용을 바꾸면 검토 대기로 돌아간다. 서명은 인쇄 후 날인하므로 출력 서명란은 비워둔다. 수행 내용도 표에 표시하여 날짜 선택이나 마우스 올리기 없이 확인할 수 있다. **이달 확정**에서 전체 확인 안내에 동의하면 검토 표시와 저장·확정을 한 번에 처리한다. 별도 날짜별 검토 체크는 요구하지 않는다. 인정시간은 출퇴근 차이에서 자동 계산하지 않는다. 미래 출근·연차 사용, 확인 필요 상태 등 서버 검증은 유지한다.
4. 월 출근부를 확정한다. 업무일지는 실제 수행의 날짜·처리자·오전/오후를 기준으로 초안을 만든다. 시간대 미확인은 별도 칸에 두고 직접 정리해야 확정할 수 있다.
5. 출근부 확정 후 일지를 검토·확정한다. 월별 인쇄는 출근일 또는 업무 내용이 있는 날짜를 출력하고 선택일 인쇄도 지원한다.
6. 확정 문서는 편집을 잠근다. 정정 사유를 남기고 다시 열어 수정·재확정한다. 이전 내용과 사유를 서버 이력에 저장한다.

## 근거와 확정 서류

- 월 문서는 선택 직원·종류·월의 고유 키로 분리한다. 선택한 직원의 실제 수행만 가져온다. 직원 전환 시 이전 직원의 편집 내용과 미리보기를 초기화한다.
- 최신 수행 가져오기는 새로운 기록을 추가하며 직접 편집한 내용을 자동 덮어쓰거나 삭제하지 않는다. 기존 수행이 수정·취소·다른 날짜로 이동했으면 직접 비교해 정정한다.
- 원본 수행·연차·기본정보 변경은 변경 알림으로 나타난다. 확정 당시 서류 내용과 근태 스냅샷은 자동 변경되지 않는다.
- 기관명 등을 바꾸어도 과거 서류를 바꾸지 않는다. 편집 중인 문서에 현재 기본정보를 명시적으로 반영할 수 있다.
- 연차 계획이 변경되면 출근부에 재확인 표시를 하고, 연차 날짜를 직접 반영할 수 있다. 변경된 연차를 검토하지 않은 출근부로는 새 업무일지를 확정할 수 없다.
- 버전 및 원본 해시로 오래된 저장·확정을 차단한다. 실패 시 입력은 유지한다.

## 연차대장

부여 일수와 시스템에 별도로 입력하지 않은 기존 사용분을 연도별로 직접 등록한다. 법정 연차 발생을 자동 계산하지 않는다. 신규 계획은 날짜별 1일/0.5일로 작성하며 사유·연락처·업무대행자·신청일을 기록한다.

- 초안 → 계획 확정: 사용 예정으로 예약.
- 계획 확정 → 사용 완료: 해당 날짜가 지난 경우 실제 사용으로 집계.
- 확정 출근부의 연차 사용과 사용 완료 계획이 같은 날짜면 중복 차감하지 않는다.
- 잔여 = 부여 − 기존 사용분 − 신규 사용. 가용 = 잔여 − 예약.
- 초과 예약·사용, 중복 날짜, 선택 직원과 다른 직원의 계획 수정은 서버에서 거부한다.
- 확정 출근부에서 사용한 연차 목록으로도 사용계획서를 작성할 수 있다.
- 계획 취소는 확정 출근부의 사용 기록을 자동 취소하지 않는다. 출근부의 사실관계는 별도로 정정해야 한다.
- 계획서 작성 확정은 전자결재 승인이 아니다. 서명·결재는 출력 서식에서 처리한다.

반복 업무의 연차 제외는 담당자 연결 후 사용할 수 있다. 확정/사용 연차 계획과 확정 출근부의 연차·반차 날짜를 기준으로 이후 생성 시 제외한다. 이미 생성된 공동업무는 조용히 삭제하지 않는다.

## 출력 서식

참고 원본: `G:/apps/miso-worker-record-from-messenger/templates`의 출근부·업무일지·휴가신청서 PNG와 기존 편집기. 원본 파일과 개인 데이터는 복사하지 않고 React 서식으로 구현했다.

- 출근부: 월간 A4 세로, 1~17일/18~말일 좌우 배치, 시간·서명·비고와 합계.
- 업무일지: 날짜별 오전/오후·비고·기타·사회복지사/시설장 결재란. 긴 내용은 여러 페이지로 흐른다.
- 연차사용계획서: 부서·직위·성명·기간·사유·연락처·대행자·신청일·서명란.
- 연차대장: 연간 부여·사용·잔여·예약과 날짜별 계획/사용 내역.

인쇄는 별도 iframe 문서로 분리하여 앱 메뉴와 인쇄 CSS의 간섭을 피한다. 미리보기는 초안에도 제공하지만 출근부·일지·계획서는 확정 후 인쇄할 수 있다. 브라우저 인쇄는 A4 세로, 배율 100%, 머리글·바닥글 해제를 권장한다. 인쇄창을 연 것만으로 실제 출력 성공을 기록하지 않는다. 실제 기관 서식과의 최종 대조 및 서명 절차는 현장 확인이 필요하다.

## 저장과 권한

인증된 `/api/work/records/*?staffId=직원ID` API를 사용한다. 서버에서 명부에 있는 직원인지 확인하고 저장 범위를 결정하며 요청자가 전달한 `ownerId`는 사용하지 않는다. 직원 선택 없는 요청은 거부한다. 허용된 로그인 계정들이 선택 직원의 문서를 함께 조회·편집할 수 있으며, 연차 일수도 직원별로 분리한다. 기록 대상과 실제 로그인 수정자(`actor_id`)를 이력에 각각 저장한다.

기존 계정에 연결된 직원은 기존 저장 키를 그대로 사용하여 문서·연차·확정 이력을 보존한다. 신규 직원은 내부 저장 키를 생성하며 구글 계정을 추가하지 않는다. 기존 이력의 수정자는 기존 소유 계정으로 보완한다. 동시 수정은 문서 버전 검사로 충돌을 막는다.

추가 테이블: `staff_record_profiles`, `staff_record_documents`, `staff_leave_accounts`, `staff_leave_plans`, `staff_record_events`. SQLite와 PostgreSQL 서버 시작 시 적용한다. PostgreSQL은 RLS와 anon/authenticated 직접 접근 차단을 적용한다. 운영 서버 재시작/배포가 필요하다.

- `tests/staff-records.test.mjs`: SQLite/Postgres 어댑터의 직원별 분리, 계정 간 공동 작성, 기존 SQLite 기록 보존·이력 마이그레이션, 실제 수정자 기록, 문서 확정·재개방, 버전 충돌, 원본 변경, 연차 집계, 출력 스냅샷, 반복 업무 연차 제외.
- `tests/work-tasks-api.test.mjs`: 실제 HTTP 인증·직원 선택 검증·계정 간 공동 작성·확정 잠금·재수정·연차 API.
- `tests/staff-records-ui.mjs`: 격리된 임시 SQLite API와 실제 브라우저를 연결해 두 계정 및 데스크톱/모바일의 작성→확정→정정→출력을 검증. 실제 운영 DB나 계정을 사용하지 않는다.
- 브라우저 테스트에서는 A4 PDF의 페이지 수를 확인했다: 출근부 1쪽, 긴 일지 2쪽, 계획서 1쪽, 연차대장 1쪽. 이 검증은 기관 원본과 픽셀 단위 일치를 보장하지 않는다.
