# 수급자 계획 보기 사용 안내

## 무엇을 볼 수 있나요?

수급자의 상태와 필요한 돌봄을 아래 다섯 메모로 나누어 확인합니다.

| 메모 | 적는 내용 예시 |
| --- | --- |
| 병력 · 건강 | 확인된 병력, 건강 상태, 돌봄 시 주의사항 |
| 요양보호사 구인조건 | 가능한 요일·시간, 필요한 요양보호사의 조건 |
| 가족사항 | 동거 가족, 보호자와의 연락 및 돌봄 협조 사항 |
| 관련병원 | 이용 병원·진료과, 방문 시 참고사항 |
| 급여제공계획 | 필요한 서비스, 제공 방식과 목표 |

관련 지인이나 업무식별명에서 병력·가족사항을 자동으로 추정하지 않습니다. ‘미등록’은 아직 적지 않은 항목입니다. 해당 사항이 없다면 ‘해당 없음’이라고 적어 주세요.

## 목록에서 빠르게 확인하기

1. 수급자 목록 위의 **계획**을 누릅니다. 기존 ‘병력’ 보기의 이름이 바뀌었습니다.
2. 수급자 옆에 다섯 메모의 앞부분이 나란히 보입니다.
3. 자세히 보려면 수급자의 행을 누릅니다. 상세 화면의 계획 영역으로 이동합니다.
4. 바로 작성하려면 해당 행의 연필 버튼을 누릅니다.

목록에서는 긴 메모를 최대 세 줄로 요약 표시합니다. 메모 원문은 자르지 않고 저장하며 상세 화면에서 전체를 읽을 수 있습니다. 작은 화면에서는 목록을 좌우로 움직여 나머지 항목을 볼 수 있습니다. 이름·담당자·상태 검색과 필터는 기존처럼 사용할 수 있고, 계획 메모 내용도 검색합니다.

## 새 계획 작성·변경

먼저 수급자의 **기관 이용계약 시작일과 만료일**을 등록합니다. 이것은 센터를 이용하는 기간입니다. 인정서에 적힌 **장기요양 인정기간**과는 구분합니다.

1. 수급자 상세에서 **계획 작성·변경**을 누릅니다.
2. **계획 종류**를 선택합니다. 처음은 신규 작성, 다음 반기는 정기 작성, 중간 변경은 인정 갱신·등급 변경·서비스 욕구 변화 중에서 고릅니다.
3. **계획 실행 시작일과 종료일**을 확인합니다.
4. 인정서의 **인정 시작일·종료일·등급**을 확인합니다. 연결한 인정서류 기간이 있으면 선택할 수 있습니다.
5. 다섯 메모와 **변경 사유**를 입력합니다.
6. 아직 작성·통보가 끝나지 않았다면 **작성 중 · 임시 저장**을 선택하여 저장합니다.
7. 끝났다면 **작성·통보 완료**를 선택하고 실제 작성일과 통보일을 입력한 뒤 저장합니다.

파일을 첨부하지 않아도 완료할 수 있습니다. 완료하려면 인정기간·등급, 실제 작성일·통보일, 급여제공계획 메모가 필요합니다. 작성자는 로그인한 계정으로 자동 기록합니다.

### 실행기간을 정하는 기관 규칙

| 상황 | 실행기간 예시 |
| --- | --- |
| 4월 15일 신규 등록 | 4월 15일 ~ 6월 30일 |
| 상반기 정기 계획 | 1월 1일 ~ 6월 30일 |
| 하반기 정기 계획 | 7월 1일 ~ 12월 31일 |
| 9월 10일 등급 변경 | 9월 10일 ~ 12월 31일 |

기관 이용기간과 인정기간이 먼저 끝나면 그 기간 안에서 계획을 정합니다. 중간 변경 계획을 완료하면 이전 계획의 실행 종료일은 변경일 전날까지로 표시합니다. 원래 저장한 기록은 지우지 않습니다. 작성 중인 변경 계획만으로 기존 계획을 종료하지 않습니다.

### 작성·통보 목표 마감일

**정기 계획은 실행 시작일 10일 전까지 작성과 통보를 모두 끝내는 것을 목표로 합니다.** 기관에서 정한 준비 목표이며 법정기한을 뜻하는 표시는 아닙니다.

| 정기 계획 실행 시작일 | 작성·통보 목표 마감일 |
| --- | --- |
| 2026년 7월 1일 | 2026년 6월 21일 |
| 2027년 1월 1일 | 2026년 12월 22일 |

- 신규 작성은 사전 마감 적용에서 제외합니다.
- 인정 갱신·등급 변경·욕구 변화에 따른 수시 변경에도 소급한 사전 마감을 강제하지 않습니다.
- 마감이 지나도 저장할 수 있습니다. 실제 날짜를 입력하면 **마감 후 완료**로 표시합니다.
- 실제 날짜를 미리 완료한 것처럼 미래 날짜로 입력할 수 없습니다.
- 실행기간이 미래인 완료 계획은 **적용 예정**, 오늘이 실행기간 안이면 **실행 중**, 기간이 끝나면 **실행 종료**로 표시합니다.
- 작성 중인 계획은 **실행 중**으로 표시하지 않습니다.

## 임시 저장한 계획을 마무리하거나 오탈자를 고칠 때

1. 계획 목록에서 해당 기간의 **작성 계속·완료** 또는 **내용 수정**을 누릅니다.
2. 내용을 확인하고 작성 상태·실제 날짜·메모를 수정합니다.
3. 변경 사유를 입력하고 저장합니다.

기존 시작일과 계획 종류는 유지합니다. 이미 등록한 인정기간 자체가 바뀌는 갱신은 새 계획으로 작성합니다. 이력의 최신 기록에서는 **이 기록의 오탈자 정정**도 사용할 수 있습니다. 저장할 때마다 이전 내용을 보존하고 새 기록을 남깁니다.

## 이전 내용 확인

**계획 변경 이력 보기**를 누르고 보고 싶은 기록을 펼칩니다.

- 당시의 다섯 메모 전체
- 적용일과 변경 사유
- 작성자와 기록일
- 현재 적용·적용 예정·이전 기록 구분

기존에 입력했던 병력·구인조건은 첫 계획 저장 때 이전 정보로 보관합니다. 예전 적용일과 작성자를 알 수 없는 경우 임의로 채우지 않고 ‘기록 없음’으로 표시합니다.

## 저장이 안 될 때

| 안내 | 할 일 |
| --- | --- |
| 적용일을 확인해 주세요 | 달력에서 실제 날짜를 다시 선택합니다. |
| 변경 사유를 입력해 주세요 | 어떤 이유로 바꿨는지 적습니다. |
| 다른 사용자가 계획을 변경했습니다 | 입력 중인 내용을 먼저 확인한 뒤 ‘최신 계획 다시 불러오기’를 누릅니다. 저장하지 않은 내용은 버려집니다. |
| 계획을 불러오지 못했습니다 | ‘다시 불러오기’를 누르거나 담당자에게 문의합니다. |

수급자 전체 정보 수정 화면에서는 병력·구인조건을 직접 바꾸지 않습니다. 계획 화면에서 변경해야 이력이 남습니다.

## 개발·운영 참고

- 새 테이블: `recipient_plans`. 이미지 저장소는 추가하지 않습니다.
- Postgres와 SQLite에서 API 시작 시 테이블을 준비합니다. 로컬은 API 재시작, Vercel은 최신 코드 재배포가 필요합니다.
- API: `GET/PUT /api/recipients/:id/plan`. 기존 승인된 Google 사용자 인증 뒤 실행합니다.
- 작성자는 서버의 검증된 사용자 ID·이름으로 기록하고, 클라이언트의 작성자·이력 값은 신뢰하지 않습니다.
- 변경 기록은 추가 방식으로 저장하고, 수급자별 버전 검사와 트랜잭션으로 동시 수정·부분 저장을 막습니다.
- 일반 수급자 목록에는 최근 메모, 실행기간과 마감일 등 계획 메타데이터를 포함합니다. 전체 이력은 상세 계획 API에서 불러옵니다.
- Postgres 테이블의 RLS를 활성화하고 anon/authenticated의 직접 접근을 취소했습니다.
- 메모는 항목당 5,000자, 사유는 1,000자까지 입력할 수 있습니다.

기존 메모에는 실행기간이나 완료일을 임의로 붙이지 않습니다. 실행 중인 계획이 없으면 최근 입력 정보로 구분하여 표시합니다.

자동 검사에는 반기 경계, 전년도 마감 계산, 신규 제외, 지연 완료, 임시 저장·완료, 이전 실행기간 조정, 동시 수정 차단을 포함합니다. 브라우저에서의 실제 화면 조작은 별도 사용자 확인이 필요합니다.
