# 종합현황에서 수급자 기초정보 연결

종합현황의 수급자 이름은 버튼이다. 이름 아래에 현재 업무식별명 또는 `업무식별명 없음`, `기초정보 미연결`, `미등록자`를 표시한다. 마우스를 올리거나 키보드로 포커스하면 업무식별명과 클릭 후 동작을 안내한다.

- 이미 연결된 수급자: 기초정보 상세로 이동한다. 업무식별명이 비어 있으면 기존 정보 수정 화면을 연다.
- 미연결이며 같은 인정번호 또는 이름의 수급자가 있는 경우: 기존 수급자 검색·연결 창을 연다. 업무식별명·인정번호를 확인해 연결하거나 별도 인물로 신규 등록할 수 있다. 이름만으로 자동 연결하지 않는다.
- 일치하는 기초정보가 없는 경우: 수급자 등록 화면을 열고 종합현황의 이름·등급·인정번호를 미리 채운다. 생년월일·주소·서비스 계약기간은 추정하지 않는다. 본인부담율은 출처 안내에 표시하며 감경 구분은 사용자가 확인한다.

상세 등록 또는 입력한 내용 임시 저장이 성공하면 해당 월·행과 수급자 ID를 연결한다. 수급자 저장 후 연결만 실패하면 등록된 수급자는 유지하고 연결만 재시도한다. 재시도는 최신 월 버전을 조회하고 원본 이름·등급·인정번호가 동일한지 확인한다. 다른 수급자에게 이미 연결되었거나 한 수급자를 같은 달 여러 행에 연결하는 경우 거부한다.

`PUT /api/work/copay?month=YYYY-MM`에 `{version,link:{id,recipientId}}`를 전달한다. 링크 변경은 기존 수납·공제·금액을 유지하고 `copay_events`에 기록한다. 연결 대상 또는 문서에 사용되는 인정번호가 바뀌면 문서 확인 상태를 초기화한다. 업무식별명은 조회 시 수급자 기초정보의 최신 값을 사용한다.

수급자 정보를 저장하고 본인부담금으로 돌아오면 같은 월·탭을 유지한 채 최신 연결을 조회한다. 저장하지 않은 수납 입력이 있으면 새 조회로 덮어쓰지 않는다.

검증: `tests/copay.test.mjs`는 SQLite·PostgreSQL 어댑터의 버전 충돌·중복 연결·수납 보존을 확인한다. `tests/copay-ui.mjs`는 실제 API를 이용해 데스크톱·모바일의 포커스 안내, 등록값 전달, 저장 후 연결·실패 재시도, 기존 수급자 연결, 업무식별명 수정 및 기존 수납 입력·문서 확인을 검증한다.
