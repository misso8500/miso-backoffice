# 불릿저널과 근무기록 통합 분석

작성일: 2026-10-19. 기능 개발 없이 `/Users/migdracios/overmind/apps/bullet-journal`의 소스·저장 스키마를 읽고 분석했다. 실행 화면·실제 저장 데이터·운영 DB는 확인하지 않았다. 기존 근무기록 분석은 [별도 문서](staff-work-records-analysis.md)를 참고한다.

## 확인된 사용자 업무

- 카카오톡으로 당일·돌발·기한형·협조 요청을 받는다.
- 예: 신규 수급자 파일 작성, 이번 주까지 급여계산, 다음 주 공동 라운딩, 내일까지 직원교육 비정형 보고.
- 사용자는 불릿저널에 기록하지만 다른 구성원은 각자의 메모 앱을 사용하여 취합할 수 없다.
- 일지는 기록을 하나씩 다시 찾아 한글 파일로 작성한다.
- 출근부·업무일지·휴가신청서 양식은 handoff 전달본과 같다.

목표는 업무 수집·계획·수행의 공동 창구에서 기록을 남기고, 이를 개괄하며 서류 작성의 반복 작업을 줄이는 것이다. 세 서류만 통합하면 그 이전의 재수집 부담이 남는다.

| 캘린더 | 날짜를 고르는 월간 패널 | 날짜 이동 기능이며 업무 일정 개괄 기능은 아님 |

제목·기한의 빠른 추가, 계획 배치, 실행 직접 기록, 취소 이력은 유지할 가치가 있다. 다만 팀의 요청자·담당자·협조자·수급자 연결·결과·대기 상태·반복 일정은 현재 스키마에 없다.

## 반드시 보완할 의미

### 실행 기록과 업무 전체 해결

현재 계획의 실행 체크는 실행을 만들고 해당 업무를 completed로 변경한다. 그러나 급여계산은 여러 날 수행하고 마지막에 마칠 수 있다. 실행 기록과 업무 전체 완료를 별도 동작으로 분리하는 것이 적절하다. 한 업무 아래 여러 수행 기록을 누적하고, 결과 확인 후 해결 처리한다. 실행 취소나 계획 취소도 전체 업무 상태를 무조건 되돌려서는 안 된다.

### 실제 수행 시각과 기록한 시각

계획을 실행으로 기록할 때 선택 날짜와 현재 한국 시각의 시·분·초를 조합한다. 과거 날짜에서 오후에 체크한 오전 업무도 오후 실행으로 기록될 수 있다. 직접 실행 입력은 선택 시간대의 정각을 저장한다. 이 값들을 곧바로 일지의 사실상 수행 시각으로 사용하면 부정확하다.

기록 시각, 실제 수행일, 실제 시간대/시각 및 미확인 여부를 구분해야 한다. 일지가 오전·오후만 필요하다면 분 단위 시간을 강요하지 않는다. 계획 시간은 실제 수행 시간의 근거로 자동 확정하지 않는다.

### 개인 소유와 공동 업무

현재 업무·계획·실행은 인증 사용자 소유이며 타인 접근을 차단한다. 여러 명이 로그인할 수 있다는 것과 업무를 공동 취합할 수 있다는 것은 다르다. 기관의 업무와 직원별 계획·수행을 연결하고 요청자·담당자·협조자를 구분해야 한다. 개인 메모와 공유 업무의 공개 범위도 필요하다.

| 신규 수급자 파일 작성 | 요청 원문/요약, 담당자, 필요 시 수급자 연결 | 서류 준비·미비 자료·작성 결과 | 실제 수행분을 일지 후보로 연결. 수급자 등록만으로 모든 서류 완성을 추정하지 않음 |
| 이번 주까지 급여계산 | 대상 월, 기한, 담당자 | 날짜별 계산·검토·보완 내용 | 수행한 날짜에 각각 반영. 최초 실행 시 업무 전체가 완료되지 않음 |

이번 주·내일·다음 주와 같은 상대 날짜는 요청 발생일을 기준으로 해석하고 확인해야 한다. 다음 주 요청은 날짜가 확정되기 전 시간 일정에 임의 배치하지 않는다. 월별 반복 업무는 대상 월별 별도 건으로 만들어 이전 달의 완료 기록을 보존하는 방향이 적절하다.

## 권장 UX

1. **빠른 수집:** 원문/짧은 문장만 먼저 기록. 정리 시 담당자·기한·대상을 보완한다. 카카오톡 자동 연동은 현재 확인되지 않았으며 도입 전제로 삼지 않는다.
2. **오늘:** 미분류 요청, 오늘 계획, 기한 임박, 대기 업무, 실제 수행을 함께 확인한다.
3. **캘린더:** 예정·기한·실적을 구분하고 직원/업무별로 본다. 날짜 미정 요청과 시간 미정 할 일도 별도 목록으로 유지한다.
4. **실행:** 계획 여부와 관계없이 짧게 남긴다. 전체 완료는 별도 선택하고 필요할 때만 결과·후속 조치를 보완한다.
5. **마무리:** 기록된 수행으로 일지 초안을 만들고 누락·시간대 미확인·근태 불일치만 검토한다. 한 일을 서식에 다시 입력하지 않게 한다.

근태·휴가는 별도 확인 사실로 연결한다. 실행 기록이나 계획의 존재만으로 출근을 확정하지 않는다. 과거 메신저 분석은 기존 기록 이관·누락 보완 경로로 유지한다.

## 기술 통합 방향

불릿저널은 Vanilla JS/Vite와 브라우저 Supabase 직접 접근, 백오피스는 React/TypeScript/Vite와 인증된 자체 API 기반이다. 현행 스키마와 RLS를 그대로 붙이면 대리 작성·공동 취합이 막히고, 개인 행 접근 제한을 단순 해제하면 공개 범위가 지나치게 넓어진다.

업무·계획·실행의 개념을 가져오고 백오피스의 인증 API 경계 안에서 직원/기관별 접근 범위를 새로 정의하는 방향을 권고한다. 기존 계정과 백오피스 직원의 연결은 인증 프로젝트/사용자 매핑 확인 후 결정한다. 코드 파일 복사나 운영 DB 변경은 이번에 수행하지 않았다.

현재 실행 추가와 업무 완료 갱신도 별도 요청으로 처리된다. 향후 함께 변경해야 하는 상태는 서버 트랜잭션으로 처리하고, 두 기기의 수정 충돌 정책을 정의한다. 기존 폴더를 공동 업무 분류로 자동 전환하지 않고 개인 폴더와 기관 공통 분류를 구분한다.

## 사용자 답변 반영: 3인 공동 업무 창구의 구체적 흐름

### 확인된 조건

- 센터장 1명: 주로 업무 지시, 일부 실무 수행.
- 사회복지사 2명: 요청 수신과 실무 수행.
- PC가 기본 업무 기기이며 모바일에서는 간단한 입력·확인.
- 센터장이 새 창구에서 직접 업무를 등록하는 방식에 긍정적. 다른 수행자가 새 요청을 빠르게 확인하는 체계는 차후 희망 사항.
- 불릿저널의 핵심 장점은 하루의 계획과 실제를 비교하며 업무 패턴을 인지하는 것.
- 주요 불편은 업무 추가와 주·월 단위 개괄.

### 제품 설계의 우선순위

업무 추가 부담을 줄이고, 일간 계획/실행의 장점을 보존하며, 같은 기록을 주·월 단위로 개괄한다. 알림·확인 응답 체계의 고도화는 후속 범위다. 기본 업무 목록에 새 요청을 표시하는 것과 푸시/외부 알림을 구분한다.

### 화면 초안

| 화면 | 핵심 구성 | 사용자 행동 |
| --- | --- | --- |
| 공통 빠른 추가 | 짧은 업무 내용, 기본 담당자, 선택적 기한/대상/협조자 | 시간표 배치나 폴더 선택 없이 먼저 저장 |
| 오늘 | 새 요청, 오늘 계획, 실제 실행, 기한 임박/대기 | 받은 일을 계획에 넣고 실행 기록. 계획 없이 실제 기록도 가능 |
| 이번 주 | 날짜 미정/시간 미정 목록과 확정 일정, 기한, 직원 필터 | 업무량·협조 일정·밀린 업무를 비교하고 재배치 |
| 이번 달 | 주요 기한, 월별 반복 업무의 해당 월 건, 라운딩·휴가 일정, 일지 확인 상태 | 빠진 업무/서류와 월 진행 상태를 개괄 |
| 하루 마무리 | 실제 수행 요약, 시간대 미확인, 근태 확인, 일지 미리보기 | 불명확한 부분만 보완하고 일지 검토 |

오늘 화면에서 일간 타임라인은 핵심으로 유지한다. 업무 추가는 타임라인 밖에서도 가능하고, 계획 시각 없이 저장할 수 있어야 한다. 주·월 화면은 날짜 선택기가 아니라 업무 내용·기한·예정·실적을 표시한다. 한 화면에 모든 항목을 겹치지 않고 보기 전환과 필터로 구분한다.

빠른 추가의 필수 입력은 우선 내용으로 제한한다. 작성자가 본인 실무를 기록할 때는 본인 담당을 기본값으로 제안하고, 센터장의 위임 요청은 최근 선택 담당자를 명시적으로 보여주되 담당자 미정으로도 수집할 수 있게 한다. 담당자 미정 건은 누구에게 배정되지 않았는지 드러낸다. 정확한 날짜·시간·분류를 입력 조건으로 강제하지 않는다. 자연어 날짜 해석은 후속 편의 기능이며 최초 구현 전제가 아니다.

### 사례별 화면 흐름

1. **신규 수급자 파일:** 센터장이 내용과 담당자를 등록 → 담당자의 새 요청 목록 → 오늘 계획에 배치하거나 바로 수행 → 준비/작성 결과를 짧게 기록 → 수행 기록으로 일지 후보 생성. 결과에 따라 업무 전체 완료.
2. **급여계산:** 센터장이 대상 월·담당자·기한 등록 → 주간 기한 목록 → 여러 날 계획/실행 누적 → 실제 처리 내용은 해당 날짜 일지 후보 → 검토까지 끝났을 때 업무 전체 완료. 월별 반복 생성은 별도 구현 범위로 결정.
3. **공동 라운딩:** 센터장이 담당자·협조자·수급자와 다음 주 일정 후보 등록 → 날짜 미정 목록 → 일정 확정 시 참여자 주간 일정에 표시 → 실제 참여자별 수행 기록 → 각자 일지 후보. 공유 일정 하나를 개인별로 중복 생성하지 않는다.
4. **직원교육 보고:** 센터장이 담당자·기한 등록 → 오늘/주간 목록 → 보고 작성 수행 → 제출 기록 → 확인/보완 대기 또는 완료. 교육 보고 작성에서 교육 실시 사실을 자동 생성하지 않는다.

### 역할과 공유 범위의 제안 — 아직 운영 규칙으로 확정하지 않음

- 센터장도 본인의 계획과 수행을 기록할 수 있다. 지시자와 수행자는 업무별 관계다.
- 사회복지사는 본인 담당 업무를 처리하고, 협조 업무에서 자신의 수행을 남긴다.
- 공동 일정은 참여자가 확인할 수 있어야 한다. 다른 사람의 일지·근태·휴가 사유 전체 공개는 별도 결정이다.
- 센터장의 전체 조회·대리 수정·일지 최종 확인 범위는 추가 확인한다. 직책만으로 자동 승인 권한을 부여하지 않는다.
- 요청 생성, 수행자 열람, 요청 수락, 계획 배치, 실제 수행, 업무 해결은 구분한다. 첫 버전에 별도 수락 버튼을 반드시 넣을 필요는 없다. 열람했다는 사실이 수락/수행을 뜻해서는 안 된다.

### 다음 설계 검증

종이 또는 정적 시안으로 빠른 추가 → 오늘 → 주간 → 월간 → 일지 후보를 이어 본다. 기존 불릿저널에서 업무 추가가 불편한 구체적인 이유는 아직 확인되지 않았으므로, 필드 수·날짜 입력·폴더 선택·화면 이동 중 어느 단계가 실제 부담인지 시안과 함께 검증한다. 사용자가 명시한 불편과 설계자의 추정을 구분한다.

남은 운영 질문은 근태·휴가의 현재 기록/확인 방식, 일지 확인 주체, 타인 업무/기록의 공개 범위다. 이는 근태 연계와 최종 권한 설계에 필요하지만 빠른 입력·주월 개괄의 시안 작성은 먼저 진행할 수 있다.

### 검토용 화면 시안

[공동 업무 창구 시안](prototypes/work-hub.html)과 [검토 순서·범위](prototypes/README.md)를 추가했다. 빠른 추가, 직원별 오늘, 주간/월간 개괄, 수행 기록에서 일지로 이어지는 흐름을 가상 사례로 확인할 수 있다. 운영 기능과 분리된 로컬 시안이며 변경은 새로고침하면 초기화된다.

### 추가 피드백: 업무 대상과 평가 대비 분류

사용자는 수급자·근로자 연결과 간단 등록, 센터 업무 체계/평가를 고려한 분류, 일지 날짜 이동을 요청했다. 사용 중인 평가 매뉴얼은 있으나 현재 공유할 계획은 없고, 건강보험공단 평가지표가 별도로 있음을 알려주었다. 현 단계에서는 매뉴얼 공유를 요구하거나 특정 공식 지표 번호를 임의로 부여하지 않는다.

업무의 담당자/협조자와 관련 수급자/근로자는 서로 다른 관계다. 관련자를 유형과 영속 ID로 연결하고, 미등록자는 이름·구분 정보로 초안 생성 후 상세 보완하는 흐름이 적절하다. 실구현에서는 기존 백오피스 간단 입력을 재사용하고, 동명이인·중복 확인·기존 기록 병합과 권한을 다뤄야 한다. 현재 시안은 가상 임시 명부만 사용한다.

분류는 두 층으로 분리하는 것을 권고한다.

1. **센터 업무 체계:** 실제 계획·배정·수행을 정리하는 안정적인 업무 분류. 시안의 다섯 분류는 합의를 위한 초안이며 미분류 수집을 허용한다.
2. **평가 기준 연결:** 적용 서비스·평가 연도/버전·지표 식별자·관련 업무/기록·증빙 상태를 관리하는 별도 대응 관계. 하나의 업무가 여러 지표와 관련될 수 있고, 하나의 지표에도 여러 기록이 필요할 수 있다. 적용 기준 확보 후 대응표를 검증한다.

평가 기준이 바뀌어도 과거 업무 분류와 기록을 다시 쓰지 않도록 연결 버전을 분리한다. 업무 등록/완료, 일지 작성, 증빙 확보, 평가 요건 충족은 구분한다. 이번 분석은 공식 평가 기준을 조회하거나 충족 여부를 판정하지 않았다.

세 서류는 공동 업무 창구와 무관한 별도 기능이 아니다. 업무일지는 실제 수행에서 직접 구성하고, 출근부는 근태의 별도 확인값으로 구성하며, 휴가서류는 계획·신청과 실제 사용 확인을 연결한다. 화면 시안에도 이 경로를 드러냈다. 출근부의 실제 편집/확정과 기존 양식에 맞춘 인쇄는 아직 남은 범위다.
