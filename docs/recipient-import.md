# 수급자 목록 엑셀 등록·업데이트

수급자 기초정보 상단의 **엑셀로 등록·업데이트**에서 파일을 선택한다. 기존 **표로 여러 명 입력**은 신규 임시등록 기능으로 유지한다.

## 사용 순서

1. 암호가 없는 `.xlsx` 파일을 선택한다. 파일당 2MB·500행, 시트당 5,000행·100열까지 지원한다.
2. 전체 시트에서 제목 행을 찾아 수급자별 신규/수정/변경 없음/오류/중복 여부를 확인한다. 인쇄용 상단 제목·병합 셀·반복 제목 행·표 하단 출력 문구를 처리한다. 장식용 그림과 그림 참조는 제외한다.
3. 변경 내용을 펼쳐 기존 값과 반영할 값을 비교한다. 빈 셀이나 없는 열은 기존 값을 지우지 않는다.
4. 같은 수급자의 계약이 여러 행이면 반영할 한 행을 직접 선택한다. 다른 계약 행은 자동으로 선택 해제된다. 동일 내용의 반복 행은 중복 제외한다.
5. 선택한 행 반영을 누른다. 신규 수급자는 기초정보 입력 중으로 생성된다. 기존 수급자는 선택한 열만 수정하며 등록 완료 여부·계약 종료/정지 상태·담당자·돌봄/건강 기록·서류·월별 서비스 명단은 유지한다.
6. 이후 기초정보 목록에서 필요한 항목을 보완한다. 파일 재선택 또는 미리보기 다시 확인으로 다시 비교할 수 있다.

## 지원 제목과 의미

| 항목 | 제목 예시 |
|---|---|
| 이름 | 성명, 이름, 수급자명 |
| 생년월일 | 생년월일 |
| 장기요양인정번호 | 인정번호, 장기요양인정번호 |
| 등급 | 등급, 장기요양등급 |
| 연락처 | 연락처, 전화번호, 수급자 연락처 |
| 주소 | 주소, 수급자 주소 |
| 보호자 | 보호자 이름/성명, 보호자 관계, 보호자 연락처/전화번호 |
| 계약 등록일 | 계약일자, 계약일, 계약등록일 |
| 이용계약 시작일 | 계약시작일, 서비스시작일 |
| 이용계약 종료일 | 계약종료일, 서비스종료일 |
| 계약 만료일 | 계약만료일 |

제목의 공백·줄바꿈은 무시한다. Excel 날짜와 `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`, `YYYYMMDD` 형식을 지원한다. 등급 `3`은 `3등급`으로, 인정번호는 `L`과 숫자 10자리로 정규화한다. 연락처·인정번호는 엑셀에서 텍스트로 보관하여 앞자리 0을 유지한다. 수식은 계산하지 않으며 해당 셀을 값으로 변환한 뒤 다시 업로드해야 한다.

계약종료일은 별도의 계약만료일 열이 없을 때 계약 만료일에도 반영한다. **최종급여 제공일자**는 계약 종료일로 해석하지 않는다. 급여종류 등 지원 목록 밖의 열은 저장하지 않는다. 기존 이용계약 기간 변경은 `service_correction` 이력에 이전 기간·엑셀 파일명을 남긴다. 갱신 업무를 자동 완료하거나 과거 계약 행 전체를 이관하지는 않는다.

## 수급자 찾기와 충돌 처리

- 인정번호를 우선 사용하며 기존 번호의 `L` 유무·대소문자는 구분하지 않는다. 같은 번호를 다시 입력해도 기존 저장값은 형식만 바꾸지 않는다.
- 번호가 없거나 번호로 찾지 못한 경우 이름·생년월일이 정확히 일치하는 유일한 수급자를 찾는다.
- 인정번호는 같은데 이름/생년월일이 다르거나, 이름·생년월일은 같은데 기존 인정번호와 다르면 오류로 표시한다.
- 동명이인 등으로 후보가 여러 명이거나 삭제된 수급자와 일치하면 자동 반영하지 않는다. 이름만으로는 기존 수급자를 찾지 않는다.
- 오류·동일 내용 중복·변경 없는 행은 선택할 수 없다. 계약 내용이 서로 다른 행은 한 행만 선택할 수 있다.

## 서버와 저장

로그인 및 허용된 업무 계정 검사 뒤 `POST /api/work/recipient-import/preview`와 `POST /api/work/recipient-import/apply`를 사용한다. 파일 원본은 DB나 파일시스템에 보관하지 않는다. 반영 요청에서도 파일을 다시 읽고 서버에서 수급자 매칭·변경 내용을 재계산한다. 클라이언트에서 보낸 수정 데이터나 대상 ID를 신뢰하지 않는다.

미리보기 결과의 지문으로 파일 내용 및 대상 수급자의 최신 버전을 비교한다. 다른 화면에서 수정했거나 먼저 반영된 파일이면 409로 거부하고 다시 확인하도록 한다. 선택한 전체 행을 하나의 트랜잭션으로 저장하므로 도중 실패하면 모두 취소한다. PostgreSQL은 쓰기 중 수급자 테이블 잠금을 사용하며 SQLite는 기존 업무 저장 큐와 트랜잭션을 공유한다. 새 DB 마이그레이션은 없다.

## 검증

- `tests/recipient-import.test.mjs`: 여러 시트·그림 참조·열/날짜 파싱, 식별·중복·오류 검증, SQLite 및 PostgreSQL 어댑터의 선택 저장·동시 수정·전체 롤백·기간 이력·재시도.
- `tests/recipient-import-ui.mjs`: 실제 임시 API와 Chrome PC/모바일 화면에서 업로드·변경 비교·계약 선택·오류 행·동시 수정 안내·저장·재업로드 검증.
- 제공된 `tmp/수급자 목록.xlsx`는 읽기 검증만 수행했다. 실제 명부에는 반영하지 않았다. 개인 정보가 있는 원본은 테스트 픽스처로 복사하지 않는다.
