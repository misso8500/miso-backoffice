# 월별 수급자–요양보호사 매칭

방문요양 서비스 관리에서 이 달의 수급자를 선택하면 ‘요양보호사 · 서비스 구분’ 열에서 기존 근로자를 연결하거나 신규 등록할 수 있다. 한 수급자에게 여러 근로자를 연결할 수 있고, 각각 방문요양/가족요양을 구분한다. 같은 근로자를 같은 수급자에 중복 연결할 수 없다. 생년월일·직종·입력 중/비활성 표시로 근로자 기록을 구별한다. 과거 월에 서비스를 제공한 비활성 근로자도 연결할 수 있다.

매칭과 수급자 선택은 ‘선택·매칭 적용’으로 함께 저장한다. 근로자를 고르지 않은 빈 연결은 선택하거나 해제해야 저장할 수 있다. 매칭이 전혀 없는 기존 수급자 명단은 그대로 저장 가능하며 상단에 미매칭 인원을 표시한다. 수정 중 월 이동·탭 이동·닫기는 기존 미저장 보호를 적용한다. 새로고침은 월별 명단과 근로자 명부를 함께 갱신한다.

신규 등록은 이름·생년월일·연락처를 기존 `POST /api/employment-contracts`로 기본정보 상태(`isDraft:true`)의 근로자 명부에 즉시 등록한다. 근로계약을 완료하거나 임금·근무조건을 설정하지 않는다. 같은 이름의 기존 근로자를 안내하고 연락처는 자동 하이픈을 적용한다. 등록 후 매칭 초안에 추가되며 월별 연결 저장은 별도로 적용한다. 신규 등록 안내에서 이 동작을 알린다.

## 데이터와 호환성

- `GET /api/work/service-workers`: 인증된 업무 사용자에게 연결용 근로자 ID·이름·생년월일·직종·활성/등록 상태만 반환한다. 주민등록번호·계좌·임금은 반환하지 않는다.
- `GET /api/work/service-month?month=YYYY-MM`: 각 수급자의 `workers`에 `workerId`, `workerName`, `birthDate`, `serviceType`을 포함한다. `workerId`는 기존 근로자/근로계약 레코드 ID다.
- 월별 PUT에 선택 사항 `workerAssignments:[{recipientId,workers:[{workerId,serviceType:'방문'|'가족'}]}]`을 보낸다. 수정한 수급자만 전달한다. 이름·생년월일은 서버가 명부에서 읽어 저장한다.
- 월별 버전 확인, 수급자 목록 변경, 매칭 변경은 같은 트랜잭션을 사용한다. 실패 시 모두 롤백하며 오래된 버전은 409로 거부한다. 충돌 시 화면의 초안을 유지한다.
- 매칭은 `recipient_service_workers`의 `(month,recipient_id)`별 JSON으로 저장한다. 기존 근로계약의 수급자 배치·근무조건과 기초정보의 서비스 구분은 변경하지 않는다. 다른 달로 자동 복사하지 않는다.
- 수급자 체크 해제와 기존 클라이언트의 매칭 없는 PUT은 저장된 매칭을 지우지 않는다. 다시 체크하면 해당 월 매칭을 복원한다. 연결을 지우려면 선택된 수급자의 연결 해제 후 적용한다.
- SQLite는 업무 스키마 초기화에서, PostgreSQL은 기존 시작 시 스키마 초기화에서 테이블을 생성한다. PostgreSQL에는 기존 업무 테이블과 같이 RLS와 직접 접근 권한 제한을 적용한다.

## 검증

`tests/recipient-service-months.test.mjs`는 SQLite/PostgreSQL 어댑터의 월별 분리, 다중 연결, 구분, 잘못된 근로자/중복 거부, 버전 충돌, 트랜잭션 롤백, 체크 해제 시 기록 보존과 명시적 해제를 확인한다.

`tests/service-worker-matching-ui.mjs`는 임시 SQLite API와 실제 앱을 사용해 PC/모바일에서 기존/신규 근로자 연결, 한 번의 월별 적용, 월 이동과 재조회, 충돌 시 초안 보존, 연결 해제와 가로 넘침을 검증한다. `tests/recipient-service-month-ui.mjs`는 기존 월별 선택·라운딩 동작을 검증한다.
