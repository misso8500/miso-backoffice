# 공동업무 반복 업무와 카테고리

## 사용

공동업무의 **반복 업무** 탭에서 나의 규칙과 카테고리를 관리한다.

- 월간: 담당자·제목·카테고리·매월 마감일을 지정한다. 해당 일이 없는 달은 말일로 조정한다.
- 일일: 현재 월의 1일부터 말일까지 생성한다. 토요일과 일요일을 각각 포함하거나 제외할 수 있다.
- 날짜 치환: `<YYMMDD>`, `<YYYYMMDD>`, `<YYYY-MM-DD>`를 지원한다. `RFID <YYMMDD> 체크`는 `RFID 261001 체크`처럼 생성된다.
- 연차 제외는 향후 근무기록·출근부·업무수행일지 연결 대상으로 보류했다. 현재 옵션은 비활성화이며 실제 생성에는 주말 설정만 적용된다.
- 나의 규칙은 로그인 계정 소유이다. 업무 담당자는 로그인 계정과 별도로 관리되는 센터 담당자 명부에서 선택한다. 생성된 업무는 기존 공동업무와 동일하게 공유된다.
- 규칙 수정은 이미 생성된 업무를 변경하지 않는다. 중지는 향후 생성을 멈추며 기존 업무는 보존한다. 재개해도 같은 발생 건을 다시 만들지 않는다.

## 자동 생성 시점

규칙 저장 시 현재 한국 시간 월분만 생성한다. 이후 공동업무의 context/tasks API 조회 시 활성 규칙의 현재 월분을 자동 확인·생성한다. 다음 달 업무는 미리 생성하지 않으며, 접속하지 않은 과거 월분도 자동으로 소급 생성하지 않는다.

**서버가 매월 1일 자정에 독립 실행하는 예약 작업은 아니다.** 해당 월 공동업무에 첫 접속할 때 생성된다. 추후 독립 스케줄러가 필요하면 서버의 `ensureRecurring()`을 호출하는 별도 운영 구성을 추가할 수 있다. 브라우저는 생성 대상 월이나 소유자를 지정할 수 없다.

규칙과 발생일(월간은 월, 일일은 날짜)의 고유 키로 중복을 막는다. 저장 재시도 식별자와 규칙 버전을 검사한다. PostgreSQL에서는 규칙 행 잠금으로 생성 요청을 직렬화한다. 월분 업무·발생 이력·생성 이벤트는 한 트랜잭션에서 일괄 저장하며 실패 시 모두 롤백한다.

## 개발자 전용 카테고리 관리

서버 환경변수에 개발자의 Google 로그인 이메일을 설정한다.

```dotenv
WORK_CATEGORY_ADMIN_EMAILS=developer@example.com
```

비어 있으면 모든 계정의 카테고리 생성·수정·삭제를 거부한다. 개발 모드인지 여부와 무관하며 API에서도 403으로 제한한다. 일반 계정은 조회만 가능하다. 환경변수는 프런트엔드의 `VITE_` 설정으로 노출하지 않는다.

삭제는 보관 처리다. 기존 업무의 카테고리 ID와 표시 이름은 유지하며 새로 선택할 수 없다. 삭제된 카테고리를 사용하는 반복 규칙의 향후 생성분은 미분류로 생성된다. 기본 미분류는 삭제할 수 없다.

## 저장과 배포

- SQLite 및 PostgreSQL의 기존 서버 시작 시 스키마 초기화에 새 테이블이 포함된다. 서버를 재시작하거나 새 버전을 배포해야 API와 테이블이 적용된다.
- `work_categories`, `work_recurrence_rules`, `work_recurrence_instances` 추가.
- PostgreSQL의 새 테이블은 RLS 및 anon/authenticated 직접 접근 차단 적용.
- 기존 업무·수행 기록을 변경하는 마이그레이션은 없다.
- 생성 이벤트에는 규칙 ID와 자동 생성 표시를 남긴다. 규칙 소유자를 요청자로, 지정한 센터 직원을 담당자로 기록한다.
