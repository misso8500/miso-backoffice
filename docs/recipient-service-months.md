# 방문요양 서비스 관리

## 라운딩 열

- 라운딩 계획은 검정(미계획), 빨강(일정조율), 노랑(서류작업), 초록(방문완료)의 네 원형 버튼으로 표시한다. 마우스를 올리거나 키보드로 포커스하면 보라색 설명이 표시되고, 선택한 상태는 테두리와 글자로 구분한다.
- 라운딩 일자는 연필 버튼에서 `yyyymmdd` 8자리로 입력한다. 연도는 4자리이며 실제 달력 날짜와 조회 월을 검증한다. 담당자도 연필 버튼에서 기존 라운딩 담당 사회복지사 명부로 선택한다.
- 이 두 열과 상태 변경은 해당 행을 즉시 저장한다. 월별 수급자 체크의 ‘선택 적용’과 별개이며, 적용 전 체크 변경을 덮어쓰지 않는다.
- 방문완료 버튼은 확인 팝업을 연다. 실제 방문일과 담당자가 있어야 확인할 수 있고, 미래 방문일의 완료는 서버가 거절한다. 취소하면 기존 상태를 유지한다.
- 확인 시 수급자·월에 해당하는 기존 라운딩 할일을 재사용한다. 없으면 하나만 생성하여 완료 처리하고, 담당자·방문일로 실제 수행과 이력을 저장한다. 전체 처리는 한 트랜잭션이므로 일부만 저장되지 않는다.
- 완료 후 날짜·담당자를 정정하면 같은 수행 기록을 수정한다. 초록에서 다른 상태로 바꾸면 할일을 재개하고 이 화면에서 만든 수행은 삭제 대신 취소 이력을 남긴다. 다시 완료해도 같은 할일과 수행 ID를 재사용한다.
- 월별 행 버전과 연결 할일의 버전을 함께 확인한다. 서비스 일시정지·취소된 할일은 기존 제한을 유지한다. 센터업무에서 완료·재개한 상태도 월별 목록 조회에 반영한다.

`recipient_service_rounding`은 수급자·월별 상태와 담당자·방문일을 저장한다. `/api/work/service-rounding?month=YYYY-MM` PUT으로 변경하고 응답으로 해당 행과 할일 캐시를 갱신한다. PostgreSQL 테이블은 서버 시작 시 기존 스키마 적용 경로로 준비한다.

수급자 메뉴의 ‘방문요양 서비스 관리’에서 연도 → 월을 선택한다. 기초정보의 전체 수급자를 리스트로 조회하며, 그 달의 대상자 체크만 별도로 저장한다. 새 달은 자동 복사하거나 자동 선정하지 않는다.

- 각 행의 ‘이 달의 수급자’를 체크하거나 해제한다.
- ‘미체크 수급자’ 필터로 아직 선택하지 않은 사람을 모아서 볼 수 있다.
- ‘현재 목록 미체크 선택’은 현재 검색·필터에 보이는 수급자만 선택한다. 검색으로 숨겨진 기존 선택은 보존한다.
- ‘선택 적용’이 변경된 월의 전체 선택을 한 번에 저장한다. 체크할 때마다 서버에 쓰지 않는다.
- 월·연도·메뉴 이동 시 적용하지 않은 변경이 있으면 확인한다. 변경 취소는 마지막 조회·저장 상태로 되돌린다.
- 수급자의 기초정보, 활성 상태, 계약 기간, 라운딩 업무는 이 체크로 변경되지 않는다. 정보 입력 중·비활성 여부도 목록에서 확인할 수 있다.

저장은 `/api/work/service-month?month=YYYY-MM` GET/PUT을 사용한다. `recipient_service_months`는 월별 선택 ID, 수정 버전, 마지막 수정 계정과 시각을 저장한다. 월별 트랜잭션 잠금과 버전 검사로 다른 사용자의 저장을 덮어쓰지 않는다. 저장 실패 시 화면의 변경은 유지한다.

SQLite·PostgreSQL 공통 스키마에 테이블을 추가했으며 PostgreSQL의 직접 클라이언트 접근은 RLS와 REVOKE로 차단한다. 기존 서버 시작 시 스키마 적용 경로를 사용하며, 개발 검증에서는 실제 운영 DB를 실행·수정하지 않았다.

검증: 두 DB 어댑터에서 월 격리·전체 해제·잘못된 ID의 원자적 거절·충돌 방지를 검사했다. PC·모바일 브라우저에서 연도/월 탭, 적용 전 쓰기 없음, 미체크 일괄 선택, 월별 선택 복원과 가로 넘침을 확인했다.
