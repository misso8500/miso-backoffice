# 수급자 도메인 모델

## 1. 문서 목적

이 문서는 `MB-003 수급자 도메인 모델 정의`의 산출물이다.

목적은 `v1.0 MVP`에서 수급자 등록, 수정, 목록 조회, 상세 조회, 계약 상태 계산, 라운딩 이력 연결에 공통으로 사용할 최소 데이터 구조를 정의하는 것이다.

이 문서에서 먼저 정의한 TypeScript 타입은 현재 로컬 SQLite 스키마와 API 계약의 기준으로 사용한다. 이후 서버형 데이터베이스로 전환하더라도 같은 도메인 필드와 내부 ID 연결 원칙을 유지한다.

## 2. 모델 설계 원칙

- 내부 연결은 `id`를 기준으로 한다.
- `longTermCareNumber`는 업무상 고유 식별자로 관리한다.
- 수급자 기본 정보, 대표 연락자 정보, 계약 날짜 정보를 하나의 수급자 모델에 포함한다.
- 라운딩 이력은 이후 `recipientId`로 수급자와 연결할 수 있게 설계한다.
- 계약 상태 계산 규칙은 `MB-006`에서 정의하되, 계산에 필요한 날짜 필드는 `MB-003`에서 미리 확보한다.

## 3. 용어 결정

수급자와 관련된 가족, 친척, 법률 대리인, 주요 의사결정자 또는 대표 연락자를 표현하는 필드명은 `guardian` 대신 `representative`를 사용한다.

`guardian`은 법정후견인 또는 보호자 의미가 강해 실제 업무에서 가족, 친척, 주요 연락자, 의사결정자를 포괄하기 어렵다. 따라서 화면과 문서에서는 `대표 연락자`, 데이터 필드에서는 `representative`를 기준 용어로 사용한다.

## 4. Recipient 모델

| 필드명 | 타입 초안 | 필수 | 한국어 표시명 | 설명 | 이후 사용처 |
|--------|-----------|------|----------------|------|-------------|
| `id` | `string` | Yes | 내부 ID | 시스템 내부에서 사용하는 수급자 고유 식별자 | 라운딩 이력 연결, 상세 조회, 수정 |
| `name` | `string` | Yes | 수급자 이름 | 수급자 본인 이름 | 목록, 상세, 등록, 수정 |
| `birthDate` | `string` | Yes | 생년월일 | ISO 날짜 문자열 기준의 생년월일 | 상세, 본인 식별 |
| `longTermCareNumber` | `string` | Yes | 장기요양인정번호 | 장기요양 업무상 수급자를 식별하는 고유 번호 | 검색, 중복 방지, 업무 식별 |
| `careGrade` | `string` | Yes | 장기요양등급 | 수급자의 장기요양 등급 | 목록, 상세, 상태 참고 |
| `phone` | `string` | No | 수급자 연락처 | 수급자 본인 연락처 | 상세, 연락 |
| `address` | `string` | Yes | 수급자 주소 | 수급자 거주지 또는 서비스 제공 주소 | 상세, 라운딩 참고 |
| `representativeName` | `string` | Yes | 대표 연락자 이름 | 수급자 관련 주요 연락 및 의사결정 담당자 이름 | 목록, 상세, 등록, 수정 |
| `representativeRelation` | `string` | Yes | 대표 연락자 관계 | 수급자와 대표 연락자의 관계 | 상세, 등록, 수정 |
| `representativePhone` | `string` | Yes | 대표 연락자 연락처 | 대표 연락자에게 연락 가능한 전화번호 | 목록, 상세, 연락 |
| `serviceStartDate` | `string` | Yes | 장기요양제공시작일 | 실제 장기요양 제공이 시작되는 날짜 | 계약 상태 계산, 상세 |
| `serviceEndDate` | `string` | Yes | 장기요양제공종료일 | 실제 장기요양 제공이 종료되는 날짜 | 계약 상태 계산, 상세 |
| `contractRegisteredDate` | `string` | Yes | 장기요양급여계약등록일 | 장기요양급여계약을 등록한 날짜 | 계약 관리, 상세 |
| `contractExpiredDate` | `string` | Yes | 장기요양급여계약만료일 | 장기요양급여계약이 만료되는 날짜 | 계약 상태 계산, 확인 필요 판단 |
| `createdAt` | `string` | Yes | 생성일시 | 수급자 데이터가 시스템에 생성된 일시 | 정렬, 관리 |
| `updatedAt` | `string` | Yes | 수정일시 | 수급자 데이터가 마지막으로 수정된 일시 | 수정 이력 참고 |

## 5. TypeScript 타입 초안

```ts
export type Recipient = {
  id: string;
  name: string;
  birthDate: string;
  longTermCareNumber: string;
  careGrade: string;
  phone?: string;
  address: string;
  representativeName: string;
  representativeRelation: string;
  representativePhone: string;
  serviceStartDate: string;
  serviceEndDate: string;
  contractRegisteredDate: string;
  contractExpiredDate: string;
  createdAt: string;
  updatedAt: string;
};
```

## 6. 유효성 기준 초안

### 필수값

아래 필드는 등록과 수정 시 반드시 입력되어야 한다.

- `name`
- `birthDate`
- `longTermCareNumber`
- `careGrade`
- `address`
- `representativeName`
- `representativeRelation`
- `representativePhone`
- `serviceStartDate`
- `serviceEndDate`
- `contractRegisteredDate`
- `contractExpiredDate`

### 선택값

아래 필드는 없더라도 수급자 등록이 가능하다.

- `phone`

### 중복 기준

- `id`는 시스템 내부에서 항상 고유해야 한다.
- `longTermCareNumber`는 업무상 고유해야 하며, 같은 번호로 중복 등록되지 않아야 한다.

### 날짜 기준

- 날짜 필드는 우선 `YYYY-MM-DD` 형식의 문자열로 관리한다.
- `serviceStartDate`는 `serviceEndDate`보다 늦을 수 없다.
- `contractRegisteredDate`는 `contractExpiredDate`보다 늦을 수 없다.
- 계약 상태 계산의 세부 규칙은 `MB-006`에서 확정한다.

## 7. 라운딩 이력 연결 초안

라운딩 이력 모델은 이후 별도 티켓에서 정의한다. 현재 단계에서는 수급자와 라운딩 이력을 아래 방식으로 연결할 수 있게 준비한다.

```ts
export type RoundingRecordDraft = {
  id: string;
  recipientId: string;
};
```

`recipientId`는 `Recipient.id`를 참조한다. `longTermCareNumber`는 업무상 조회와 중복 방지에 유용하지만, 사람이 입력하고 관리하는 값이므로 내부 관계 연결의 기준은 `id`로 둔다.

## 9. 다음 티켓 영향

### MB-004 수급자 목록 및 상세 조회 구현

목록 화면은 우선 아래 필드를 중심으로 구성할 수 있다.

- `name`
- `careGrade`
- `phone`
- `representativeName`
- `representativePhone`
- `contractExpiredDate`

상세 화면은 `Recipient` 모델의 전체 필드를 표시하는 방향으로 시작한다.

### MB-005 수급자 등록 및 수정 구현

등록과 수정 폼은 이 문서의 필수값과 선택값 기준을 따른다. 폼 검증 도구 도입 여부는 `MB-005`에서 결정한다.

계약 상태 계산은 아래 날짜를 기준으로 확장한다.

- `serviceStartDate`
- `serviceEndDate`
- `contractRegisteredDate`
- `contractExpiredDate`
