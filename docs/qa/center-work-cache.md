# 센터업무 공유 조회 캐시

## 동작

- 센터업무 공통 데이터는 인증 세션의 메모리 캐시에 보관한다. 서버 응답을 브라우저 저장소나 파일에 영구 저장하지 않는다.
- 구성원·일반 할일·월별 태스크 맵·일간 기록·달력 범위·반복 규칙·분류·업무 이력을 대상으로 한다. 아직 조회하지 않은 달이나 달력 범위는 처음 열 때 추가로 조회한다. 라운딩과 직원 문서 등 다른 API는 기존 조회 방식을 유지한다.
- 같은 URL의 동시 조회는 하나의 Promise를 공유한다. 60초 이내 데이터는 네트워크 요청 없이 재사용한다.
- 오래된 캐시가 있으면 우선 표시하고 백그라운드로 조회한다. 화면 복귀·탭 활성화 때는 현재 구독 중인 오래된 데이터만 다시 확인한다. 별도 주기 폴링은 하지 않는다.
- 실제 업무 탭 전환 자체는 강제 새로고침하지 않는다. 명시적인 새로고침은 캐시를 무효화하고 조회한다.
- 저장 성공 응답으로 태스크 맵·일반 할일·계획·수행·기존 반복 규칙·분류를 갱신한다. 응답만으로 복원할 수 없는 관계 데이터(달력·관련 이력 등)만 오래된 것으로 표시해 필요 시 재확인한다.
- 이전 조회가 늦게 도착해 최신 저장 응답을 덮어쓰지 않도록 캐시 갱신 버전을 검사한다. 실패한 저장은 완료로 표시하지 않으며 재조회가 가능하도록 캐시를 무효화한다.
- 로그인 계정 변경·로그아웃·인증 실패 시 캐시를 비운다. 이전 인증 세션의 늦은 응답은 캐시에 다시 넣지 않는다.

## 검증

- 단위 테스트: 동시 요청 합치기, 재사용, 만료 후 화면 유지와 갱신 통지, 구독 범위만 재확인, 네트워크 실패 후 마지막 데이터 유지, 저장/조회 순서 역전, 세션 초기화 후 늦은 응답 차단.
- 브라우저: 지도→설계→투두에서 같은 월 GET 1회 공유, 저장 응답의 탭 간 재사용, 61초 경과 후 focus 이벤트로 서버 변경분 반영, 기존 상세 편집·달력·실제 수행 날짜 수정·반복규칙 중지/재개 검증.

다른 사용자의 변경은 화면 복귀나 만료 후 해당 범위 조회 때 반영된다. 즉시 푸시 동기화는 제공하지 않는다. 저장 시 기존 서버 버전 충돌 검사는 유지한다.
