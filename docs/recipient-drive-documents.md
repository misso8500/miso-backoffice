# 수급자 Drive 서류 연결

## 구현 결과

수급자 상세 화면의 ‘수급자 서류’는 이제 서버에 저장한 Drive 연결을 읽는다. 화면을 다시 열어도 신분증과 인정 기간별 서류를 볼 수 있다. 기존 수급자 화면의 저장되지 않는 인정 이력 체험 컴포넌트는 이 기능으로 교체했다. 근로자 서류 연결은 아직 별도 개발 대상이다.

이미지 원본은 Drive에서 읽으며 우리 저장소로 복사하거나 업로드하지 않는다. 데이터베이스에는 수급자 ID, 폴더 ID, 파일 ID, 문서 종류, 인정 기간, 페이지 순서, 파일 이름, 변경 버전을 저장한다. 인정 기간은 이용계약 기간과 독립적이다.

최초 대상의 서류 5장을 조회하고 사용자가 확인한 인정 기간 **20260909~20280908**로 Supabase에 연결 저장·재조회했다. 처음 전달된 날짜와 실제 폴더 이름이 달라 사용자에게 확인한 뒤 저장했다. 실명·개인 문서 파일 ID는 이 문서에 기재하지 않는다.

## 사용자 사용 순서

### 이미 연결된 서류 보기

1. 로그인한 뒤 수급자 목록에서 대상자를 누른다.
2. 상세 화면의 **수급자 서류**를 확인한다.
3. 신분증은 공통 서류에 표시된다.
4. 인정 기간 아래에는 인정서·이용계획서·복지용구확인서가 나누어 표시된다.
5. 사진을 누르면 전체 이미지가 보인다. 작은 글씨는 **확대해서 읽기**를 누른 뒤 스크롤한다.
6. **이전 장·다음 장** 또는 방향키로 같은 인정 기간의 서류 전체를 이어서 확인한다.

썸네일과 확대 화면은 내려받은 사진을 공유한다. 이미 읽은 사진은 다시 내려받지 않고, 확대 화면에서 앞뒤 사진도 미리 읽는다. 사진은 열린 수급자 상세 화면의 메모리에만 임시 보관하며 화면을 닫거나 다른 수급자로 이동하면 해제한다. 브라우저 저장소나 별도 이미지 저장소에 보관하지 않는다. 처음 읽는 사진은 네트워크 상태에 따라 잠시 기다릴 수 있다.

이미 연결된 서류는 다시 ‘불러오기’나 ‘저장’을 누르지 않아도 된다.

### 처음 연결하거나 새 사진 추가하기

1. **드라이브 서류 연결** 또는 **서류 추가·연결 수정**을 누른다.
2. 해당 수급자의 사람별 폴더 링크를 입력한다.
3. **폴더의 사진 불러오기**를 누른다. 하위 폴더의 JPG·PNG·WebP도 함께 조회한다.
4. 인정서에 적힌 유효기간을 입력한다. 기존 기간과 같다면 추가할 필요 없다.
5. 연결할 사진의 체크칸을 누른다.
6. 서류 종류와 인정 기간, 쪽 순서를 지정한다. 신분증은 인정 기간을 선택하지 않는다.
7. **서류 연결 저장**을 누르고 저장 완료 안내를 확인한다.

선택을 해제하고 저장하면 업무 시스템에서의 연결만 해제된다. Drive 원본은 삭제되지 않는다. 편집 취소나 저장 전 화면 닫기는 기존 연결을 변경하지 않는다. 같은 사진을 두 문서에 중복 연결하거나 같은 서류 묶음 안에서 쪽 번호를 중복 지정할 수 없다.

다른 사용자가 먼저 수정했다는 안내가 나오면 화면을 닫고 다시 열어 최신 연결을 확인한 뒤 수정한다.

## 관리자 설정

- 기존 서비스 계정 인증과 Drive API 활성화를 유지한다.
- 권장: Vercel 또는 `.env.local`의 `DRIVE_RECIPIENT_ROOT_IDS`에 수급자 상위 폴더 ID를 등록한다. 여러 개면 쉼표로 구분한다. 링크 전체가 아닌 ID만 넣는다.
- 이 설정이 있으면 하위 사람 폴더를 개별 등록하지 않아도 된다. 서버가 Drive의 부모 폴더를 따라 올라가 승인된 상위 폴더 안에 있는지 확인한다.
- 기존 `DRIVE_RECIPIENT_FOLDER_IDS`는 개별 사람 폴더를 직접 승인하는 예외 설정으로 계속 지원한다. 상위 폴더 범위로만 통일하려면 필요한 기존 연결이 포함되는지 확인한 뒤 이 개별 목록을 비운다.
- 서비스 계정에도 해당 폴더 뷰어 공유가 필요하다. 공유 권한만 부여해도 서버의 승인 목록에 없으면 조회할 수 없다.
- 한 사람 폴더를 서로 다른 수급자에게 중복 연결할 수 없다.
- 환경 변수 변경 후 API를 재시작한다.
- Postgres와 SQLite 모두 시작 시 `recipient_documents` 테이블을 준비한다. 첫 실제 Postgres 테이블은 이미 준비했다.
- Postgres 테이블은 RLS를 켜고 anon/authenticated 직접 접근을 취소했다. 기존 서버의 승인 사용자 인증을 통과한 요청만 처리한다.

## 범위와 제한

상위 폴더 승인 방식에서는 폴더 조회·연결 저장·이미지 조회 요청마다 선택한 사람 폴더가 승인된 상위 폴더 안에 있는지 확인한다. 사람 폴더가 밖으로 이동하면 다음 요청부터 차단된다. 각 이미지도 부모 폴더를 따라 올라가 연결한 사람 폴더 안에 있는지 확인한다. 부모 확인은 최대 12단계이며 바로가기는 따라가지 않는다. 휴지통 파일, 승인 폴더 밖 파일, 바로가기, SVG·PDF 등 지원하지 않는 형식은 제공하지 않는다. 하위 폴더 탐색은 깊이 8단계, 50개 폴더, 전체 이미지 300장까지 제한한다. 파일은 20MB 이하만 제공한다. 이미지 응답은 no-store이며 썸네일은 보이는 위치에 가까워질 때 읽는다.

현재는 원본을 내려받아 화면에서 축소 표시하므로 운영 규모가 커지면 축소 이미지 전송을 별도 검토해야 한다. 배포 인증은 로컬 데스크톱 JSON 경로로 해결되지 않으며 별도 설정이 필요하다. PDF 보기, OCR 자동 분류, 근로자 서류 연결은 이번 범위에 포함하지 않았다.

## 검증

- 실제 Drive 대상 폴더의 서류 5장 조회 성공
- 실제 Supabase 대상 수급자 유일성 확인, 연결 저장 후 재조회 성공
- 날짜·중복·승인 폴더·폴더 밖 파일·휴지통 상위 폴더·동시 수정 검증
- 실제 브라우저 화면 조작은 아직 검증하지 않음
