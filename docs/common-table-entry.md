# 수급자·근로계약 공통 표 입력

CSV 예제 다운로드와 CSV 업로드 기능을 두 화면에서 제거했다. 표 입력은 `src/BasicEntryGrid.tsx`를 함께 사용한다. 엑셀 셀 복사·붙여넣기는 계속 지원하며 파일 업로드가 아니다.

## 사용 흐름

1. 각 관리 화면에서 **표로 여러 명 입력**을 누른다.
2. 이름만 필수로 입력하고 나머지는 아는 만큼 작성한다. Tab 이동, 여러 셀 붙여넣기, 10행 추가, 행 삭제를 지원한다.
3. 한 번에 최대 100행을 저장한다. 저장 후 **정보 입력 중** 목록에서 확인한다.
4. 이름을 누르고 **상세 정보 입력**에서 나머지를 보완한다.
5. **입력한 내용 임시 저장**으로 여러 번 나누어 서버에 저장할 수 있다.
6. 필수 정보를 모두 채우면 **상세 정보 등록 완료**로 전환한다.

### 수급자 열 순서

이름 → 생년월일 → 장기요양인정번호 → 등급 → 연락처 → 주소

### 근로계약 열 순서

근로자 이름 → 주민번호 → 연락처 → 은행 → 계좌번호 → 계약 시작일 → 계약 종료일

주민번호는 미입력으로 저장할 수 있으며, 입력한다면 앞 7자리 또는 전체 13자리를 사용한다. 날짜는 `20260101` 등 지원 형식을 표에서 정규화한다. 연락처·계좌·식별번호는 엑셀에서 텍스트로 관리해 앞자리 0을 보존한다.

표는 신규 등록용이다. 같은 이름은 기존 데이터 안내만 표시하며 동명이인 또는 같은 근로자의 추가 계약인지 확인한다. 이름만으로 기존 자료를 덮어쓰거나 같은 사람으로 자동 병합하지 않는다. 전체 주민번호가 같아지면 기존 근로자별 목록 묶기 기준이 적용된다.

## 근로계약의 입력 중 상태

- `employment_contracts.is_draft`로 구분한다. 기존 계약은 기본값 false로 유지한다.
- 미입력 주민번호·계좌·기간·근무시간을 가짜 정보로 채우지 않는다. 임금의 내부 미입력값은 0이며 화면에는 **약정 미입력**으로 표시한다.
- 등록 중인 계약은 올해 유효 계약 건수에서 제외한다. **등록 상태 → 정보 입력 중**에서 모아 본다.
- 기간·근무시간·약정액이 아직 불완전해도 임시 저장할 수 있다. 입력한 값이 잘못된 날짜·음수 등이면 수정해야 한다.
- 등록 완료 시에는 필수 근로자 정보·계약 기간·임금·근무 조건을 검증한다. 완료 후에도 매칭 대기라면 운영상 유효 계약과 구분한다.
- 추가/갱신계약은 상세 등록 완료 이후 사용한다. 기존 계약의 수정·갱신·조건 이력·주민번호 가림은 유지한다.

## 저장과 개발

- `POST /api/recipients/bulk-drafts`, `POST /api/employment-contracts/bulk-drafts`에서 로그인·허용 계정을 확인한다.
- 묶음 저장은 트랜잭션으로 처리한다. 실패 시 새로 저장할 묶음 전체를 취소한다.
- 행 ID가 유지되므로 같은 기본 정보의 재시도는 기존 등록을 반환한다. 기존 정보를 덮어쓰지 않는다. 같은 ID의 기본 정보가 다르거나 등록 완료된 데이터라면 409로 거부한다.
- 상세 화면의 임시 저장은 기존 JSON API를 사용하며 수급자별 조건의 부분 입력도 보관한다. 상세 등록 완료 시 불완전한 기존 조건을 생략해서 검증을 우회할 수 없다.
- 새 DB 열은 API 시작 시 마이그레이션으로 적용한다. 대상 DB 확인 후 `npm run supabase:init`으로 먼저 적용할 수도 있다.

주요 파일: `src/BasicEntryGrid.tsx`, `src/App.tsx`, `src/storage.ts`, `server/employment-drafts.mjs`, `server/recipient-drafts.mjs`, `server/work-conditions.mjs`.

검증: `node --test tests/*.test.mjs`, `npm run build`. 실제 HTTP 테스트는 임시 SQLite DB와 가짜 인증 서버를 사용한다. 운영 PostgreSQL에서의 저장·새로고침·상세 보완은 API 재시작 후 별도로 확인한다.
