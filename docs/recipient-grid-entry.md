# 수급자 최소 정보 표 입력

## 사용하는 순서

1. 수급자 관리에서 **표로 여러 명 입력**을 누른다.
2. 한 행에 한 명씩 입력한다. 이름만 필수이며 생년월일·장기요양인정번호·등급·연락처·주소는 선택이다.
3. 엑셀에서 제목 행을 제외한 셀을 복사해 표의 시작 셀에 붙여넣을 수 있다. 열 순서는 이름, 생년월일, 장기요양인정번호, 등급, 연락처, 주소다. Tab으로 다음 셀로 이동한다.
4. 오류와 동일 이름 안내를 확인한 뒤 **N명 저장**을 누른다. 빈 행은 제외하며 한 번에 100명까지 저장한다.
5. 저장한 수급자는 **정보입력중** 목록에 나타난다. 이름을 누르고 **상세 정보 입력**에서 나머지를 채운다.
6. 아직 정보가 부족하면 **입력한 내용 임시 저장**으로 여러 차례 보완한다. 이 내용도 서버에 저장되어 새로고침 후 유지된다.
7. 필수 상세 정보를 모두 채우고 **상세 정보 등록 완료**를 누르면 정상 수급자 상태로 전환된다.

신규 수급자 등록 기능이다. 기존 수급자를 엑셀 내용으로 일괄 수정하는 기능은 아니다. 같은 이름은 동명이인일 수 있어 안내만 표시하고, 장기요양인정번호 중복은 막는다.

생년월일은 `19440510`, `1944-05-10`, `1944.5.10`, `1944/05/10` 형식을 표 저장 시 정규화한다. 등급은 `3` 또는 `3등급`처럼 입력한다. 엑셀의 연락처·인정번호는 텍스트로 관리해야 앞자리 0을 보존할 수 있다.

## 저장과 오류 처리

- `POST /api/recipients/bulk-drafts`가 로그인·허용 계정 검사 뒤 저장한다.
- 여러 행을 사전 검증하고 한 DB 트랜잭션으로 저장한다. 어느 한 행이 충돌하면 새로 저장할 묶음을 전체 취소한다.
- 표의 행 ID는 입력 중 유지한다. 같은 행과 내용으로 재시도하면 기존 임시 등록을 반환하므로 응답 유실 후 재시도로 중복 생성되지 않는다.
- 동일 ID의 내용이 이미 수정됐거나 등록 완료됐다면 덮어쓰지 않고 409로 거부한다.
- 저장 오류가 발생해도 표 입력은 유지된다. 저장하지 않고 닫으려 하면 확인 메시지를 표시한다. 새로고침 전의 미저장 표 내용은 보관되지 않는다.

## 데이터 구조

`recipients.is_draft`를 추가했다. 기존 레코드는 기본값 `false`로 유지한다. 이름 외의 미입력 개인정보·계약 기간은 빈 값으로 저장한다. 임시 등록은 계약 만료·갱신 대상에서 구분하며, 상세 날짜가 비어 있어도 화면이 오류 없이 열린다.

인정번호 열의 기존 NOT NULL·UNIQUE 제약을 유지하기 위해, 인정번호가 없는 임시 등록은 `__draft__:<행 ID>`라는 내부 식별값을 사용한다. 실제 인정번호를 만들어 넣는 것이 아니며 API 응답·사용자 화면에는 빈 값으로 반환한다. 상세 정보 완료 시 실제 인정번호로 교체한다. 이 내부 값은 직접 SQL 조회 시 보일 수 있으므로 추후 직접 SQL 내보내기를 만들 때도 필터링해야 한다.

Postgres는 `server/postgres/schema.sql`, SQLite는 시작 시 마이그레이션으로 새 열을 추가한다. API 재시작 또는 대상 DB 확인 후 `npm run supabase:init` 적용이 필요하다.

## 코드와 검증

- `src/BasicEntryGrid.tsx`: 표 입력, 붙여넣기, 오류 표시, 저장
- `src/lib/recipient-grid.ts`: 엑셀 탭 구분 텍스트 파싱과 생년월일 정규화
- `server/recipient-drafts.mjs`: 임시 등록 기본값, 배치 검증, 재시도 비교
- `server/api.mjs`, `server/postgres/api.mjs`: 배치 트랜잭션과 상세 보완 저장
- `src/App.tsx`: 등록 중 상태, 목록, 상세 임시 저장·등록 완료
- `tests/recipient-grid.test.mjs`: 붙여넣기·미입력·중복·재시도 규칙
- `tests/work-conditions-api.test.mjs`: 임시 SQLite API에서 이름만 저장, 재시도, 부분 수정, 등록 완료, 실패 시 전체 취소 검증

```bash
node --test tests/*.test.mjs
npm run build
```

실제 Supabase 환경에서는 API 재시작 후 이름만 두 명 저장, 새로고침, 상세 일부 저장, 등록 완료, 엑셀 다중 셀 붙여넣기를 수동 확인한다. 자동 API 검증은 운영 데이터 대신 임시 SQLite DB와 가짜 인증 서버를 사용한다.
