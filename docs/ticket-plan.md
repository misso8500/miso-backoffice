# 티켓 개발 수행 문서

## 1. 문서 목적

이 문서는 개발 명세서를 실제 구현 가능한 작업 단위로 나누기 위한 문서이다.

목표는 다음과 같다.

- 1인 개발자가 순차적으로 실행할 수 있는 티켓 구조 제공
- 각 티켓의 완료 조건을 명확히 정의
- MVP 범위를 벗어나는 작업이 섞이지 않도록 관리

## 2. 티켓 운영 원칙

- 티켓은 가능한 한 한 가지 결과물을 중심으로 나눈다.
- 기능 구현 전에 데이터 구조와 권한 영향을 먼저 확인한다.
- 각 티켓은 완료 조건과 확인 방법을 가져야 한다.
- 문서 작업은 구현을 돕는 수준으로만 포함한다.
- 장기 확장 도메인은 반영하되, 이번 티켓 범위에는 넣지 않는다.

## 3. 선행 티켓 그룹

### T-001 프로젝트 초기 구성

- 목표: 개발을 시작할 수 있는 기본 실행 환경 구성
- 주요 작업
  - 프로젝트 생성
  - 기본 디렉터리 구조 정리
  - TypeScript 기반 실행 환경 정리
  - 데이터베이스 연결 준비
  - 기본 환경 변수 구조 정의
- 산출물
  - 실행 가능한 프로젝트 베이스
  - 초기 폴더 구조
  - 환경 변수 예시
- 완료 조건
  - 개발 서버가 실행된다.
  - 기본 페이지가 렌더링된다.
  - 데이터베이스 연결 준비가 완료된다.

### T-002 공통 개발 규칙 정리

- 목표: 이후 구현에 공통으로 적용할 최소 규칙 정의
- 주요 작업
  - 네이밍 규칙 정리
  - 도메인 폴더 구조 기준 정리
  - 공통 유효성 검사 방식 정리
  - 날짜 처리 기준 정리
- 산출물
  - 코드 작성 기준 초안
  - 공통 유틸 구조 초안
- 완료 조건
  - 이후 티켓에서 같은 기준을 반복 적용할 수 있다.

## 4. MVP 핵심 티켓 그룹

### T-101 인증 및 사용자 역할 기초

- 목표: 내부 사용자 로그인과 최소 권한 체계 구성
- 주요 작업
  - 로그인 기능 구현
  - 사용자 역할 정의
  - 보호 페이지 접근 제어
  - 인증된 사용자 정보 조회 방식 정리
- 연관 도메인
  - User
  - Role
- 완료 조건
  - 로그인 성공/실패 흐름이 동작한다.
  - 인증되지 않은 사용자는 내부 페이지에 접근할 수 없다.
  - 사용자 역할을 코드에서 참조할 수 있다.
- 확인 방법
  - 로그인 전후 접근 가능한 페이지 차이를 확인
  - 역할 값이 세션 또는 서버 로직에서 확인 가능

### T-102 담당자/사용자 데이터 모델 구성

- 목표: 수급자와 연결될 담당자 구조 마련
- 주요 작업
  - 사용자 모델 정의
  - 담당자 표현 방식 결정
  - 관리자 역할 데이터 시드 또는 초기 데이터 준비
- 연관 도메인
  - User
  - Manager
- 완료 조건
  - 담당자로 선택 가능한 사용자 데이터가 존재한다.
  - 수급자와 연결 가능한 구조가 준비된다.
- 확인 방법
  - 관리자 목록을 조회할 수 있다.

### T-103 수급자 데이터 모델 및 DB 스키마 구현

- 목표: 수급자 관리의 기준이 되는 데이터 구조 확정
- 주요 작업
  - Recipient 모델 정의
  - 필수 필드 반영
  - 담당자와의 관계 정의
  - 생성일/수정일 관리
- 연관 도메인
  - Recipient
- 완료 조건
  - 수급자 테이블이 생성된다.
  - 필수 필드와 관계가 스키마에 반영된다.
- 확인 방법
  - 마이그레이션 또는 스키마 반영 확인

### T-104 수급자 등록 기능

- 목표: 수급자를 새로 등록할 수 있는 기능 구현
- 주요 작업
  - 등록 폼 UI 구현
  - 서버 저장 로직 구현
  - 필수값 및 날짜 유효성 검사
  - 담당자 선택 기능 구현
- 완료 조건
  - 수급자 등록이 가능하다.
  - 잘못된 입력은 저장되지 않는다.
- 확인 방법
  - 정상 입력 시 저장 확인
  - 빈 값, 잘못된 날짜 입력 시 오류 확인

### T-105 수급자 목록 조회 기능

- 목표: 수급자 목록을 백오피스 형태로 조회 가능하게 구성
- 주요 작업
  - 목록 테이블 UI 구현
  - 기본 조회 API 또는 서버 데이터 조회 구현
  - 담당자 정보 표시
  - 계약 상태 표시를 위한 기본 컬럼 구성
- 완료 조건
  - 수급자 목록이 화면에 표시된다.
  - 담당자와 계약 종료일을 함께 확인할 수 있다.
- 확인 방법
  - 데이터가 테이블에 정상 표시되는지 확인

### T-106 수급자 상세 및 수정 기능

- 목표: 등록된 수급자 정보를 상세 조회하고 수정할 수 있게 구성
- 주요 작업
  - 상세 페이지 구현
  - 수정 폼 구현
  - 수정 저장 로직 구현
  - 수정 후 목록/상세 반영 확인
- 완료 조건
  - 수급자 상세 정보를 볼 수 있다.
  - 기존 정보를 수정하고 저장할 수 있다.
- 확인 방법
  - 수정 전후 데이터 비교

### T-107 수급자 삭제 기능

- 목표: 수급자 삭제 처리 구현
- 주요 작업
  - 삭제 액션 UI 구현
  - 삭제 확인 절차 반영
  - 삭제 서버 로직 구현
- 완료 조건
  - 사용자가 삭제를 수행할 수 있다.
  - 삭제 후 목록에서 제거된다.
- 확인 방법
  - 삭제 후 재조회 시 데이터가 존재하지 않음

### T-108 계약 만료 상태 계산 로직

- 목표: 계약 종료일 기반 상태 계산 규칙 구현
- 주요 작업
  - 상태 계산 유틸 또는 서버 로직 구현
  - `normal`, `expiring`, `expired` 기준 반영
  - 재사용 가능한 형태로 분리
- 완료 조건
  - 기준 날짜에 따라 상태가 정확히 계산된다.
- 확인 방법
  - 경계값 날짜 테스트
  - 15일 전, 당일, 지난 날짜 케이스 확인

### T-109 계약 상태 표시 UI

- 목표: 목록에서 계약 상태를 시각적으로 구분
- 주요 작업
  - 상태 배지 또는 강조 UI 구현
  - 상태별 색상 또는 라벨 규칙 적용
- 완료 조건
  - 사용자가 목록에서 만료 임박 대상자를 바로 식별할 수 있다.
- 확인 방법
  - 상태별 UI 구분 확인

### T-110 검색, 필터, 정렬 기능

- 목표: 수급자 목록 탐색 기능 강화
- 주요 작업
  - 이름 검색
  - 등급 필터
  - 계약 상태 필터
  - 담당자 기준 조회
  - 정렬 기능
- 완료 조건
  - 주요 조건으로 목록을 좁혀서 확인할 수 있다.
- 확인 방법
  - 각 검색/필터/정렬 조건별 결과 확인

### T-111 역할 기반 수급자 조회 제한

- 목표: 사용자 역할에 따라 조회 가능한 데이터 제한
- 주요 작업
  - 관리자 전용 전체 조회 처리
  - 담당자 전용 본인 데이터 조회 처리
  - 서버 단 권한 검증 추가
- 완료 조건
  - `admin`과 `manager`의 조회 범위가 다르게 동작한다.
- 확인 방법
  - 서로 다른 계정으로 목록 비교

## 5. 품질 보강 티켓 그룹

### T-201 공통 에러 처리 및 사용자 피드백

- 목표: 저장 실패, 권한 오류, 검증 오류를 명확히 전달
- 주요 작업
  - 에러 메시지 규칙 정리
  - 폼 오류 표시
  - 서버 오류 표시
- 완료 조건
  - 주요 실패 상황에서 사용자가 다음 행동을 이해할 수 있다.

### T-202 핵심 로직 테스트

- 목표: 비즈니스 규칙과 핵심 입력 검증을 보호
- 주요 작업
  - 계약 상태 계산 테스트
  - 입력 유효성 검사 테스트
  - 권한 분기 테스트
- 완료 조건
  - 핵심 규칙에 대한 자동 확인 수단이 있다.

### T-203 기본 배포 준비

- 목표: MVP를 외부에서 확인 가능한 상태로 준비
- 주요 작업
  - 환경 변수 점검
  - 배포 대상에 맞는 설정 반영
  - 데이터베이스 연결 검증
- 완료 조건
  - 최소 1개 환경에서 앱을 실행할 수 있다.

3. `T-101` 인증 및 사용자 역할 기초
4. `T-102` 담당자/사용자 데이터 모델 구성
5. `T-103` 수급자 데이터 모델 및 DB 스키마 구현
6. `T-104` 수급자 등록 기능
7. `T-105` 수급자 목록 조회 기능
8. `T-106` 수급자 상세 및 수정 기능
9. `T-107` 수급자 삭제 기능
10. `T-108` 계약 만료 상태 계산 로직
11. `T-109` 계약 상태 표시 UI
12. `T-110` 검색, 필터, 정렬 기능
13. `T-111` 역할 기반 수급자 조회 제한
14. `T-201` 공통 에러 처리 및 사용자 피드백
15. `T-202` 핵심 로직 테스트
16. `T-203` 기본 배포 준비

## 7. 이번 문서의 사용 방식

- 개발을 시작할 때 현재 진행할 티켓 하나만 선택한다.
- 구현 중 범위가 커지면 새 티켓으로 분리한다.
- 장기 확장 항목은 별도 티켓 그룹으로 분리하고, 이번 MVP에 섞지 않는다.
- 실제 구현이 진행되면 각 티켓에 상태와 메모를 추가해 관리한다.
