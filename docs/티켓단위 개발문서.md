# 티켓단위 개발문서

## 1. 문서 목적

이 문서는 `Miso Backoffice v1.0 MVP`를 실제 구현 가능한 단위로 분해한 실행 문서다.

이 프로젝트에서 티켓은 단순 메모가 아니라 아래 역할을 함께 가진다.

- 바로 구현 가능한 최소 작업 단위
- 검증 가능한 완료 기준의 기준서
- `1티켓 = 1커밋` 원칙의 기준점
- 학습기록과 연결되는 출발점

즉, 이 문서에 적힌 티켓은 구현 전에 범위를 고정하고, 구현 후에는 커밋과 학습기록의 기준이 된다.

## 2. 프로젝트 목표

`v1.0 MVP`의 목표는 수급자 관리 흐름 1개를 끝까지 연결하는 것이다.

시스템은 최소한 아래 질문에 답할 수 있어야 한다.

- 현재 등록된 수급자는 누구인가
- 수급자의 기본 정보는 무엇인가
- 각 수급자의 계약 상태는 어떤가
- 최근 라운딩 기록은 무엇인가
- 지금 확인이 필요한 수급자는 누구인가

## 3. 운영 규칙

### 3.1 티켓과 커밋 규칙

- 모든 구현 작업은 티켓 단위로 시작한다.
- 하나의 티켓은 원칙적으로 하나의 커밋으로 마감한다.
- 하나의 커밋에 여러 티켓의 결과를 섞지 않는다.
- 티켓 범위가 너무 크면 구현 전에 더 작은 티켓으로 다시 쪼갠다.
- 커밋 전에는 해당 티켓의 `Done Criteria`와 `Verification`을 다시 확인한다.

권장 커밋 메시지 형식은 아래와 같다.

```text
[TICKET-ID] 작업 요약
```

예시:

```text
[MB-001] Initialize project structure and development documents
```

### 3.2 티켓 완료 규칙

이 프로젝트에서 `Done`은 아래 4가지를 모두 만족해야 한다.

1. 티켓 범위의 구현이 끝났다.
2. 검증 절차를 수행했다.
3. 관련 문서를 반영했다.
4. 학습기록 문서에 강의 수준의 설명을 남겼다.

### 3.3 학습기록 품질 규칙

모든 티켓은 완료 후 반드시 학습기록과 연결한다.

학습기록은 인수인계 메모 수준으로 끝나면 안 되며, 아래 수준을 목표로 한다.

- 왜 이 순서로 작업했는지 설명할 수 있어야 한다.
- 왜 다른 대안이 아니라 이 구조를 선택했는지 설명할 수 있어야 한다.
- 처음 보는 사람이 다시 구현할 수 있을 정도로 절차가 드러나야 한다.
- 코드 결과가 아니라 개념과 판단이 남아 있어야 한다.

## 4. Epic 구성

## [EPIC-01] 프로젝트 기반과 운영 문서 체계 확정

### Objective

개발을 시작하기 전에 문서, 폴더, 실행 기준, 기록 규칙을 먼저 고정하여 이후 모든 티켓이 같은 방식으로 진행되게 만든다.

### Success Condition

- 프로젝트 목표와 MVP 범위가 문서로 정리되어 있다.
- 티켓 문서와 학습기록 문서가 준비되어 있다.
- 첫 구현 티켓이 정의되어 바로 개발을 시작할 수 있다.
- 커밋 단위 규칙과 학습기록 규칙이 프로젝트 문서에 명시되어 있다.

### Included Tickets

- MB-001 프로젝트 문서 구조와 실행 규칙 정리
- MB-002 기술 스택 및 기본 애플리케이션 구조 확정

## [EPIC-02] 수급자 기본 정보 관리 흐름 구축

### Objective

수급자 데이터를 시스템에 등록하고, 수정하고, 조회할 수 있는 가장 기본적인 관리 흐름을 완성한다.

### Success Condition

- 수급자 기본 정보 데이터 구조가 정의되어 있다.
- 수급자 등록, 목록 조회, 상세 조회, 수정 흐름이 연결되어 있다.
- 최소한의 유효성 기준이 문서화되어 있다.

### Included Tickets

- MB-003 수급자 도메인 모델 정의
- MB-004 수급자 목록 및 상세 조회 구현
- MB-005 수급자 등록 및 수정 구현

## [EPIC-03] 계약 상태와 라운딩 이력 추적 흐름 구축

### Objective

수급자 데이터가 단순 보관에 머무르지 않고, 계약 상태와 라운딩 이력을 통해 다음 확인 행동을 드러내는 수준까지 발전시킨다.

### Success Condition

- 계약 시작일과 종료일을 기준으로 상태를 구분할 수 있다.
- 확인이 필요한 수급자를 식별할 수 있다.
- 최소 단위의 라운딩 기록을 등록하고 조회할 수 있다.

### Included Tickets

- MB-006 계약 상태 규칙 정의 및 상태 표시 구현
- MB-007 라운딩 기록 모델 정의 및 입력 구현
- MB-008 수급자별 이력 화면 구성

- Priority: `P1`

### 2. Scope
