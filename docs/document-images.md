# 수급자·근로자 서류 이미지 보기

> 수급자 화면은 [실제 Drive 서류 연결](recipient-drive-documents.md)로 교체되었습니다. 아래 저장 전 미리보기 설명은 초기 구현 기록과 근로자 화면에 해당합니다.

## 현재 구현 범위

상세 화면에서 문서 종류별로 JPG·PNG·WebP 이미지를 선택하고 썸네일을 눌러 확대할 수 있다. 여러 장은 이전 장·다음 장 또는 좌우 방향키로 넘긴다. Escape는 이미지 보기만 닫고 상세 화면은 유지한다.

현재 단계는 **브라우저 내 미리보기**다. 이미지·인정 기간은 서버나 드라이브에 저장되지 않는다. 화면을 닫거나 다른 수급자·계약으로 이동하면 초기화된다. 원본 드라이브 파일은 변경하지 않는다. 선택 순서가 페이지 순서이며 실제 연결 단계에서 명시적인 페이지 순서 저장이 필요하다.

## 문서 구분

| 대상 | 묶음 | 문서 |
| --- | --- | --- |
| 수급자 | 사람 공통 | 신분증 |
| 수급자 | 인정 유효기간별 | 장기요양인정서, 개인별장기요양이용계획서, 복지용구확인서 |
| 근로자 | 선택한 근로계약별 | 근로계약서 (1부 3매 기준) |
| 근로자 | 사람 공통 | 범죄경력 회보서 (1부 3매 기준), 요양보호사 자격증, 건강검진 확인서 |

인정 유효기간은 수급자 이용계약 기간과 별개다. 기존 이용계약 날짜로 인정 기간을 자동 생성하지 않는다. 여러 인정 기간을 입력하여 서류를 각각 미리볼 수 있다. 같은 시작일·종료일의 중복은 차단한다.

근로자 공통 서류는 실제 저장 연동 단계에서 연도별 계약이 아닌 동일 근로자에 연결할 계획이다. 현재 미리보기 파일은 다른 계약으로 이동하면 유지되지 않는다. 범죄경력 회보서와 건강검진 확인서는 재발급된 문서를 구분할 수 있도록 발급일·문서 이력을 추후 저장해야 한다.

## 확인된 드라이브 운영 조건

- 사용자는 Google Workspace의 공유 드라이브를 사용한다.
- 승인된 앱 사용자 세 명은 모든 수급자·근로자 서류를 열람해도 된다.
- 현재 앱의 Google 로그인 성공만으로 Drive 읽기 권한이 생기는 것은 아니다. 이번 작업은 로그인 범위를 변경하지 않았다.

## 실제 공유 드라이브 조회를 위해 남은 작업

1. 기존 폴더 구조와 문서 파일명 규칙을 확인한다. 이름만으로 사람을 자동 연결하지 않고 앱의 수급자·근로자 식별자와 명시적으로 연결한다.
2. 원본을 읽을 서버 인증 방식과 공유 드라이브 관리자 정책을 확인한다. 승인된 대상 폴더만 읽게 구성한다. 인증 비밀 값은 프론트엔드 환경 변수에 넣지 않는다.
3. 인정 이력, 사람 공통 서류, 계약별 서류 및 각 페이지의 Drive 파일 ID를 저장하는 구조를 마련한다. 문서 메타데이터에는 개인정보 원문을 URL 키로 사용하지 않는다.
4. 서버에서 앱 로그인·승인 사용자·문서 연결 관계를 확인한 뒤 이미지를 가져온다. 임의의 Drive 파일 ID나 외부 URL을 브라우저가 지정해서 조회하게 만들지 않는다.
5. 공유 드라이브 파일의 접근 권한 철회, 삭제, 이동 및 인증 만료 시 안내와 재시도를 제공한다. 개인정보 이미지 응답의 공유 캐시를 막는다.

테스트 폴더의 Drive 조회는 구현되었다. 상세 내용은 [Drive 연결 점검](drive-connection.md)을 참고한다. 사람·계약·인정 기간별 연결과 영구 저장은 아직 구현되지 않았다.

## 화면 점검 순서

1. 수급자 상세 → 공통 신분증 이미지 선택 → 썸네일 확대 → 닫기.
2. 인정 기간 두 개 입력 → 서로 다른 이미지를 선택 → 묶음이 섞이지 않는지 확인.
3. 잘못된 인정 기간과 같은 기간 중복 입력 시 오류 확인.
4. 근로계약 상세 → 계약서 3장 선택 → 확대 후 이전·다음 및 방향키 확인.
5. Escape로 확대 화면만 닫히고 상세 화면이 남는지 확인.
6. 계약서 2장 선택 시 3매 확인 안내, JPG 외 지원하지 않는 형식 선택 시 안내 확인.
7. 다른 계약·사람으로 이동하거나 상세 화면을 닫은 뒤 다시 열면 선택 파일이 사라지는지 확인.

타입 검사와 프로덕션 빌드는 통과했다. 실제 브라우저 조작은 아직 검증하지 않았다. 테스트 폴더의 PNG 이미지 3개는 서버에서 조회 성공했다.
