# 수급자 입력·조회 개선

## 계약일 수정과 갱신

수급자 상세의 **계약 기간 수정·갱신**을 누른다.

- 실제 계약 갱신: 새 계약서에 적힌 시작일과 만료일을 함께 입력한다.
- 오탈자 정정: 잘못된 날짜만 고친다.
- 인정서의 인정 유효기간과 이용계약 기간은 별개다. 계약 기간을 수정해도 Drive 인정서류 기간은 바뀌지 않는다.

이 경로에서는 다른 신상정보가 미완성이어도 기간만 저장할 수 있다. 등록 단계나 활성 상태를 자동 변경하지 않는다. 날짜 변경 전·후를 서버가 변경 이력으로 기록하며, 상세에서 **계약 기간 변경 이력 보기**로 확인한다. 변경 이력은 이번 기능으로 수정한 시점부터 기록된다. 동일한 날짜를 다시 저장하면 이력을 추가하지 않는다. 다른 사용자의 선행 수정이 있으면 저장을 거부하고 다시 열도록 안내한다.

전체 정보 수정에서도 필수 항목과 날짜 오류를 화면의 저장 버튼 근처에 표시하고 해당 안내로 이동한다. 과거 저장 무반응의 가능한 원인으로 전체 필수 항목 또는 브라우저 날짜 유효성 차단이 있었다. 실제 사용자 브라우저에서의 최초 재현은 하지 않았으며, 저장 실패 안내와 별도 기간 수정 경로로 개선했다.

## 날짜 입력

사용자 피드백에 따라 날짜 입력은 기존 브라우저 달력(`input type="date"`)으로 되돌렸다. 연도·월·일을 각각 별도 입력칸으로 나누거나 강제로 포커스를 옮기지 않는다.

달력 선택과 브라우저의 기본 키보드 입력을 유지한다. 최소·최대 날짜를 4자리 연도 범위로 지정하며, 날짜 값에 5자리 이상 연도가 들어오면 저장 상태에 반영하기 전에 4자리로 제한한다. 브라우저 내부의 미완성 날짜 표시와 구간 이동은 브라우저 기본 동작을 따른다.

표 입력은 엑셀처럼 여러 셀을 붙여넣는 기존 날짜 텍스트 입력을 유지한다. 표의 날짜는 기존 정규화·검증을 사용한다.

## 창 닫기

수급자·근로계약 상세 및 수정 창, 삭제·해지·복구 확인 창에서 바깥 배경을 누르거나 Escape를 누르면 닫는다. 여러 창이 겹쳐 있으면 Escape는 가장 위 창부터 닫는다. 이미지 확대 창에서는 이미지 창만 닫는다. 표 입력 창의 미저장 내용 확인 동작은 유지한다.

## 목록 보기

목록 상단의 **기본 / 병력 / 유효 / 주소** 버튼으로 표시 항목을 전환한다.

| 보기 | 표시 내용 |
| --- | --- |
| 기본 | 등급·인정번호, 주요 연락처, 서비스 구분, 담당자 |
| 병력 | 병력·건강 메모, 구인조건, 주요 연락처, 등급 |
| 유효 | 계약 상태, 이용계약 시작일·만료일, 활성 상태 |
| 주소 | 전체 주소, 본인 연락처, 대표 연락자, 담당자 |

수급자 이름을 누르면 기존처럼 상세를 연다. 검색과 상태·담당자 필터는 보기 전환 시 유지한다. 작은 화면에서는 표를 가로로 스크롤해 각 항목을 확인한다.

병력·건강 메모는 전체 정보 수정에서 입력한다. 기존 업무식별명이나 서류 사진을 분석해 병력을 추정하지 않는다. 기존 자료는 새 메모를 입력하기 전까지 ‘병력 미등록’으로 표시된다.

## 실행과 검증

- API를 재시작하면 `recipients.medical_history` 열을 준비한다. Vercel에는 최신 코드를 재배포해야 한다.
- 실제 업무 데이터의 날짜나 병력을 임의로 변경하지 않았다.
- 임시 SQLite로 기간만 수정, 변경 이력, 동시 수정 충돌, 잘못된 기간 거부, 병력 저장·유지와 기존 일괄 입력을 검증했다.
- 날짜 검증 및 프로덕션 빌드를 통과했다.
- 브라우저 기본 날짜 입력과 배경 클릭·Escape의 실제 조작은 사용자 확인이 필요하다.
