# 수급자 삭제

기존 DELETE 처리는 `enabled=false`만 저장하고, 명부 GET은 비활성 수급자도 조회했다. 화면은 삭제 직후 로컬 목록에서 제거했으므로 새로고침하면 다시 나타났다. 비활성 상태는 계약 종료에도 사용되므로 `enabled`만으로 삭제를 판정할 수 없다.

`recipient_deletions`에 삭제 표식을 저장한다. DELETE는 비활성화·삭제 표식·삭제 이력을 하나의 트랜잭션에서 처리하며 재요청해도 삭제 이력을 중복 생성하지 않는다. 명부·서비스 대상·RFID·라운딩·신규 업무 연결 대상에서 삭제된 수급자를 제외하고 기본정보 상세 조회·수정을 거부한다. 계약 종료로만 비활성화된 수급자는 계속 조회한다.

이전 삭제로 생성된 `deactivated` 이력이 있고 현재 비활성이며 그 이후 복귀·재계약 이력이 없는 수급자는 서버 시작 시 삭제 표식을 보완한다. 단순히 비활성이라는 이유만으로 삭제 처리하지 않는다. SQLite와 PostgreSQL 양쪽에 적용한다.

관련 계약·업무·청구·수납 기록은 보존한다. 종합현황의 원본 행은 `삭제된 수급자`로 표시하여 명부 삭제와 구분한다. 삭제 이후 명부 조회 캐시를 무효화하고, 삭제 이전에 시작한 목록 요청이 뒤늦게 도착해 화면에 다시 추가하지 않도록 처리한다.

검증: `tests/work-tasks-api.test.mjs`의 삭제 회귀 시나리오에서 삭제·재조회·서버 재시작·과거 삭제 보완·계약 종료 보존·삭제 실패 롤백을 확인한다. `tests/copay-ui.mjs`에서 데스크톱·모바일 실제 삭제와 새로고침, 청구·수납 이력 보존을 확인한다.
