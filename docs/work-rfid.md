# RFID 업무 관리

센터 업무 → 일일 업무 관리(투두) → RFID에서 사용한다. 방문요양 서비스 관리의 월별 대상 선택을 조회해 `이 달의 서비스 수급자`로 필터링할 수 있다.

수급자 이름을 누르면 월간 달력이 슬라이드 다운으로 펼쳐진다. `서비스 정보`에서 해당 월의 총 근무일·총 근무시간·근무 유형·내용을 저장한다. 평일은 월~금, 월~토는 일요일 제외이며 공휴일은 별도로 제외하지 않는다. 지정일은 날짜 버튼으로 선택한다. 서비스 계약 기간 밖은 예정일에서 제외한다. 총 근무일·시간은 사용자가 입력한 서비스 기준이며, 달력의 예정일 수 및 RFID 확인 수와 각각 표시한다.

달력에서 날짜를 선택하면 데스크톱은 오른쪽, 좁은 화면은 달력 아래에 업무내역 패널이 펼쳐진다. 확인 체크는 비고와 함께 즉시 저장하며 취소 체크도 가능하다. 비고만 수정한 경우 `비고·내역 저장` 또는 Ctrl+Enter를 사용한다. 미래 날짜는 비고 작성만 가능하다. 예정 외 날짜도 별도 확인을 기록할 수 있다.

저장되지 않은 변경이 있으면 화면 이동을 제한하며 `변경 취소`로 해제할 수 있다. 저장 실패 시 입력을 유지한다. 버전 충돌 시 `최신 내역 불러오기`를 선택하면 확인 후 미저장 변경을 버리고 최신 상태를 불러온다.

## 저장 및 운영

- `GET /api/work/rfid?month=YYYY-MM`: 수급자 및 월별 설정·확인 내역 조회.
- `PUT /api/work/rfid?month=YYYY-MM`: `recipientId`, `version`, `kind`를 포함한다. `settings`는 서비스 정보를, `day`는 `date`, `checked`, `note`를 저장한다.
- `work_rfid_months`에 월·수급자를 복합 키로 저장한다. 버전으로 동시 수정을 감지하며 설정 변경은 일자별 기록을 덮어쓰지 않는다. 비활성 수급자도 저장된 월의 내역은 조회할 수 있다. 저장자·저장 시각을 기록한다.
- 기존 반복 RFID 업무는 재생성하지 않는다. 이 화면은 수급자별 월간 확인 내역을 직접 관리한다. 외부 RFID 전송 시스템과 자동 대조하는 기능은 포함하지 않는다.
- SQLite는 서버 시작 시 테이블이 준비된다. PostgreSQL은 배포 전 기존 스키마 적용 절차(`npm run db:postgres:init`)로 새 테이블과 RLS를 적용해야 한다.

서비스 정보 입력 위치는 RFID 화면에 두었으며, 추후 방문요양 서비스 관리에서도 같은 월·수급자 데이터를 편집하도록 확장할 수 있다.

## 검증

`node --test tests/work-rfid.test.mjs`와 `tests/work-rfid-ui.mjs`로 날짜·서비스 기간 계산, 월/수급자 격리, 체크·비고·설정 저장, 충돌·트랜잭션 롤백, 데스크톱/모바일 조작을 확인한다. UI 테스트는 다른 UI 테스트와 동일하게 `WORK_UI_PLAYWRIGHT_MODULE` 및 필요 시 `WORK_UI_CHROME_PATH`를 지정한다.
