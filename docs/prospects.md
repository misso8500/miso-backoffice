# 잠재고객 관리

**수급자 → 잠재고객 관리**에서 계약 전 연락처와 상담·실사 방문, 다음 확인 일정을 관리한다. 기존 수급자 명단과 별도로 저장하며 등록만으로 수급자를 생성하거나 서비스 대상 인원에 포함하지 않는다.

## 화면과 업무

- 연락처 접수 / 상담 중 / 실사 방문 예정 / 점검 완료·대기 / 서비스 수급 유보 / 타 센터 선택·거절 / 계약 연결을 구분한다.
- 이름을 먼저 등록할 수 있다. 고객·보호자 연락처, 주소, 유입 경로, 상담 요청, 담당자와 접수일은 나누어 보완한다.
- 관리 중·오늘 확인·확인일 지남·실사 방문 예정 숫자로 대상 명단을 바로 좁힌다. 단계·담당자·검색·보관함 필터도 제공한다.
- 명단에서 다음 확인일이 지난 고객부터 표시한다. 상세는 화면 안의 패널로 열고, 긴 내용은 패널 안에서 스크롤한다.
- 다음 업무는 이 명단에서 추적하는 한 건의 후속 조치다. 센터업무 할일을 자동 생성하지 않는다.
- 연락·상담·실사 방문·메모를 실제 활동일과 함께 기록한다. 예정 업무를 실제로 마친 경우에만 ‘이 기록으로 업무 완료’를 선택한다. 이 선택은 다음 일정만 비우고 진행 단계를 자동 변경하지 않는다.
- 유보·종결은 사유를 필수로 남긴다. 계약 연결·종결 저장 시 남은 다음 확인 일정을 종료하고 이전 일정은 변경 이력에 보존한다.
- 보관은 삭제가 아니며 보관함에서 복원할 수 있다. 보관 중에는 새 활동 기록을 막는다.
- 계약 연결은 이미 계약 정보를 등록한 수급자를 선택한다. 기존 상담 이력은 유지하고 수급자를 중복 생성하지 않는다. 수급자 등록 화면으로 정보를 자동 이관하는 기능은 아직 포함하지 않는다.

## 저장과 검증

- `GET /api/work/prospects`: 명단, 담당자와 계약 연결 후보.
- `POST /api/work/prospects`: 잠재고객 등록.
- `GET /api/work/prospects/:id`: 상세와 전체 기록.
- `PUT /api/work/prospects/:id`: 정보·단계·다음 일정·보관 상태 변경.
- `POST /api/work/prospects/:id/activities`: 실제 활동 기록과 선택적인 다음 업무 완료.
- 모든 요청은 기존 서버의 인증·이메일 허용 목록 검사를 사용한다. 수정은 조회 버전을 검사하고, 고객 변경과 이력은 한 트랜잭션으로 저장한다. 기록에는 실제 로그인한 작성자를 남긴다.
- PostgreSQL은 `server/postgres/schema.sql`, SQLite는 `server/prospects-schema.sql`로 두 테이블을 초기화한다. PostgreSQL RLS 및 anon/authenticated 직접 접근 차단을 포함한다. API가 시작될 때 스키마를 초기화하므로 실행 중인 API는 새 코드로 재시작해야 한다.
- `node --test tests/prospects.test.mjs`: SQLite·PostgreSQL 어댑터의 단계/활동 분리, 다음 업무 완료, 보관·복원, 충돌, 중복 등록, 계약 연결, 원자적 롤백, API 디스패치와 SQLite 재개 후 보존을 검증한다. PostgreSQL 어댑터 검증은 SQLite SQL 브리지이며 실제 운영 PostgreSQL 검증은 아니다.
- `tests/prospects-ui.mjs`: 실제 임시 API를 사용한 PC·모바일 브라우저 검증 스크립트.
