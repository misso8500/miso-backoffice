# 센터 운영 서비스 기능표

작성일: 2026-10-27  
문서 상태: 실무자와 함께 수정하는 기획 초안

## 1. 서비스가 먼저 답해야 하는 질문

사용자는 월중 목적에 따라 사람을 검색하기도 하고, 처리할 대상 목록에서 업무를 시작하기도 한다. 짧게 접속해도 다음 내용을 파악하고 필요한 업무로 이어갈 수 있어야 한다.

1. 이번 달 내가 해야 할 일은 무엇인가?
2. 이번 달 관리할 대상은 누구인가?
3. 새로 들어오거나, 이탈하거나, 유지되는 인원은 누구인가?
4. 아직 관리하지 못한 사람은 몇 명이며, 무엇이 남았는가?
5. 지금 선택한 사람에게 다음으로 해야 할 일은 무엇인가?

## 2. 이 문서의 수정 방법

- 아래 표는 개발 완료 목록이 아니라 만들고 싶은 서비스의 기능 목록이다. 현재 구현 여부는 개발 전에 별도로 점검한다.
- `논의 상태`: 방향 합의 / 제안 / 기준 결정 필요 / 보류 / 제외.
- `우선순위`: P1 먼저 필요 / P2 다음 단계 / P3 추후 검토. 현재 값은 제안이며 변경할 수 있다.
- 기능을 없애려면 행을 지우기보다 `제외`로 표시하고 이유를 남긴다. 기능 ID는 유지한다.
- 실무자는 `실무 의견·수정` 칸에 원하는 명칭, 실제 처리 방법, 불필요한 항목을 적는다.
- 보험·퇴직금·교육 등의 대상과 기한은 아직 확정하지 않았다. 아래 항목만으로 법적 처리 기준이나 자동 계산 규칙을 정하지 않는다.

이름으로 시작하는 흐름도 유지한다: **이름 검색 → 사람별 요약 → 필요한 업무 바로 처리**.

| RULE-08 | 재직과 배정 | 재직 상태와 실제 배정 상태는 분리. 사회복지사 등 배정이 필요 없는 경우 구분 | |
| RULE-09 | 계약과 실제 이용 | 계약 유효 여부와 실제 서비스 이용 상태를 분리 | |
| RULE-10 | 과거 월 조회 | 현재 상태로 과거 숫자를 덮어쓰지 않고 해당 시점의 적용일·이력으로 집계 | 정정된 과거 기록의 집계 반영 기준은? |
| RULE-11 | 내 업무 기준 | 로그인 계정이 아닌 선택 직원·업무 담당자 기준으로 조회 가능 | 선택 직원 유지 방식과 공유 범위는? |

## 9. 화면에 공통으로 적용할 원칙

| 원칙 | 화면에서의 구체적인 동작 |
|---|---|
| 숫자에서 명단으로 이어진다 | 현황 숫자를 누르면 동일 월·담당자·조건의 명단을 연다 |
| 명단에 이유를 표시한다 | ‘갱신 대상’뿐 아니라 만료일·진행 상태·다음 행동을 함께 표시한다 |

| 긴 입력과 이력은 상세로 나눈다 | 모든 정보를 첫 화면에 펼치지 않고 필요한 항목으로 바로 이동한다 |
| 같은 사람을 다시 찾지 않는다 | 상세에서 돌아와도 월·검색·필터·목록 위치를 유지한다 |
| 정상 항목을 반복 확인시키지 않는다 | 예외와 미처리를 우선 표시하되 전체 명단도 볼 수 있다 |
| 대량 처리는 근거와 대상 확인 후 수행한다 | 단순히 전체 선택했다는 이유로 계약·신고·서류 상태를 완료로 바꾸지 않는다 |
| 원본은 하나다 | 사람별 수정이 업무별 명단과 현황에 함께 반영된다 |
| 적용일과 수정 이력을 남긴다 | 누가 언제 무엇을 바꿨는지, 실제 상태가 언제부터 적용되는지 구분한다 |

## 11. 실무자 답변에 따른 방문 관리 개발 기준

아래 기준은 실무자가 직접 답한 내용이다. 앞의 제안 표와 다르면 이 절을 우선한다. 아직 결정되지 않은 경우는 구현 시 임의로 확정하지 않는다.

### 11.1 관리 대상과 상태

관리 범위는 서비스 이용 계약자로 한정한다.

| 상태 | 관리 목적 | 화면에 필요한 정보 |
|---|---|---|
| 서비스 제공 중 | 전체 명단과 총인원 확인. 상태 자체에 대한 별도 작업은 없음 | 제공 중 명단·총인원, 해당 월 방문 진행 |
| 서비스 신규 시작 | 신규 계약 후 서비스를 막 시작한 초기 관리 대상 확인 | 서비스 시작일, 담당 사회복지사, 초기 관리·방문 진행 |
| 서비스 일시정지 | 개인 사유 등으로 중단한 사람의 복귀 시점을 계속 파악 | 정지 사유·시작일·복귀 예정일, 복귀 일정 확인 필요 여부 |
| 서비스 해지 요청 | 해지 처리를 진행하고 관리 명단에서 제외 | 해지 요청과 처리 상태, 제외 처리 여부 |

‘서비스 제공 중’의 별도 작업이 없다는 것은 월별 방문 의무가 없다는 뜻이 아니다. 해지 요청과 실제 해지 처리를 구분하며, 종료된 사람의 과거 기록은 삭제하지 않는 방향으로 설계한다.

### 11.2 방문 할일과 담당자

| 항목 | 실무자 답변 |
|---|---|
| 기본 생성 | 대상자별 매월 방문업무 1건 |
| 월중 신규·제공 | 월중 서비스가 제공되는 경우에도 반드시 해당 월 방문업무에 포함 |
| 일시정지 | 일시정지자는 방문업무를 진행하지 않음 |
| 담당자 선택 | 사회복지사 2명 중 드롭다운으로 직접 선택. 월별 담당자가 다를 수 있음 |
| 완료 기준 | 연결된 방문업무 태스크를 완료하면 방문 완료로 판단 |
| 할일 연동 | 센터업무(할일)과 연결하여 동일한 방문업무를 처리 |
| 담당자 변경 | 인수인계 업무 생성, 미완료 업무 이관, 새 담당자의 방문업무는 새로 진행 |
| 서비스 종료 | 남은 업무는 자동 제외하지 않고 사용자가 직접 제외하도록 안내 |
| 월중 진행 | 방문 예정과 미수행을 구분 |
| 기한 | 월말을 넘기지 않도록 미완료 방문업무를 반드시 강조 표시 |

### 11.3 시스템 설계에 반영할 원칙

다음은 위 답변을 구현하기 위한 설계 방향이며, 사용자 답변 그 자체와 구분한다.

- 대상 명단에서 방문 할일을 열고, 할일 완료 결과가 명단의 방문 상태에 반영되도록 같은 태스크를 연결한다.
- 기본 월별 생성의 중복을 막되, 담당자 변경으로 필요한 새 방문은 별도 이력을 가진 예외로 관리한다.
- 이미 완료한 방문과 담당자 변경 이력을 보존한다. 새 방문이 필요한 사람을 기존 방문 완료만으로 관리 완료 처리하지 않는다.
- 담당자 미선택은 누락시키지 않고 ‘담당자 지정 필요’로 표시한다.
- 복귀일 미정은 정상 복귀 예정과 구분하여 확인할 대상으로 표시한다.
- 제외는 완료와 구분하고 사유를 남긴다. 해지자에 대한 자동 제외는 수행하지 않는다.
- 기한 초과가 실제 발생한 경우에도 목록에서 사라지지 않도록 유지한다. 미완료는 평소에도 표시하고 월말 7일 전부터 경고를 강화한다.

### 11.4 추가 확인으로 확정된 기준

아래 세 항목은 실무자가 후속 답변에서 모두 동의했다. 제안이 아닌 개발 기준으로 적용한다.

| 항목 | 확정 기준 |
|---|---|
| 담당자 변경 예외 | 기존 담당자가 해당 월 방문을 완료했더라도 새 담당자의 방문업무를 생성하고 다시 진행한다. 기존 완료 이력은 보존한다. 인수인계 업무 생성과 미완료 업무 이관도 함께 적용한다. |
| 월중 정지·복귀 | 정지 중에는 기존 미완료 방문을 보류한다. 같은 달 복귀하면 기존 미완료 방문을 재개한다. 이미 완료한 방문은 정지·복귀만을 이유로 추가 생성하지 않는다. 담당자 변경 시 재방문 기준은 별도로 적용한다. |
| 월말 경고 | 평소에도 미완료 방문을 표시하고, 월말 7일 전부터 경고를 강화한다. |

### 11.5 후속 정의가 필요한 항목

| 항목 | 남은 질문 | 제안 — 아직 확정 아님 |
|---|---|---|
| 초기 관리 범위 | 신규 상태를 언제 끝내며 방문 외에 어떤 초기 관리가 필요한가? | 별도 기준이 정해질 때까지 초기 관리 완료를 자동 판정하지 않음 |
| 요청 중 해지 | 해지 요청 이후 실제 종료일까지 방문 대상에 포함하는가? | 서비스가 실제 제공 중인 기간과 해지 처리일을 구분하여 결정 필요 |

등급신청 대기부터 서비스 시작까지의 과정 관리는 이번 답변에서 개발 포함 여부가 확정되지 않았다. 현재 방문 관리 범위인 ‘서비스 이용 계약자’와 구분한다.
