말씀하신 업무를 보면, 지금의 ‘계약 조건’은 **계약서에 적힌 조건, 수급자별 근무 조건, 변경 이력, 월별 보험 상태**를 담아야 합니다. 이를 하나의 값을 수정하는 방식으로 처리하면 과거 기록과 실제 지급 기준이 섞입니다.

제 제안은 **계약서는 보존하고, 실제 적용 조건은 시작일을 정해 이력으로 쌓는 구조**입니다.

**먼저 보험 기준은 그대로 자동화하면 안 되는 부분이 있습니다.**

| 말씀하신 기준 | 개발 전에 확인할 사항 |
|---|---|
| 59.5시간 이하이면 고용·산재만 적용 | 월 소정근로시간인지 실제 근무시간인지 구분해야 합니다. 국민연금은 시간 외에 소득 등 가입 요건도 있어 시간 하나로 확정하기 어렵습니다. |
| 국민연금은 만 65세부터 제외 | 일반적인 사업장가입 연령 기준은 **60세 미만**입니다. 65세 기준으로 구현하면 오류가 생깁니다. |
| 만 65세 이상이면 고용보험 제외 | 실업급여 적용과 고용보험 전체를 구분해야 합니다. 65세 이전부터의 계속 고용 여부도 확인해야 합니다. |
| 겸직 시 급여가 높은 곳에서 4대보험 모두 징수 | 네 보험을 하나의 규칙으로 제외하면 안 됩니다. 보험별 자격·중복가입 기준을 따로 확인해야 합니다. |

국민연금공단은 연령뿐 아니라 단시간 근로자의 시간·소득 요건을 안내하고 있고, 고용노동부도 65세 이후 신규 고용과 계속 고용을 구분합니다. [국민연금 가입 연령](https://data.nps.or.kr/pportal/main/listWorkPlace.do?arg=list&cmsid=102020102000), [단시간 근로자 가입 요건](https://www.nps.or.kr/pbcpgdnc/mainbiz/getOHAG0058M0.do), [65세 관련 고용보험 안내](https://1350.moel.go.kr/home/hp/data/faqView.do?faq_idx=1000001157)

따라서 첫 버전은 **보험별로 ‘적용 / 제외 / 확인 필요’를 담당자가 확정**하고, 제외 사유·확인 근거·적용 월을 남기는 방식이 적합합니다. 자동 판정은 기준을 확정한 뒤 보조 기능으로 추가하겠습니다.

**계약 상태와 매칭 상태도 나누는 것이 좋겠습니다.**

매칭되지 않았다는 사실을 시스템에서 표시할 수는 있지만, 체결한 근로계약이 법적으로 무효인지까지 자동 판단해서는 안 됩니다. 화면에는 실제 업무 상태를 표현하는 것이 정확합니다.

| 상황 | 제안하는 표시 |
|---|---|
| 계약 작성 후 수급자와 연결 전 | **매칭 대기** |
| 수급자와 연결됐지만 근무 시작 전 | **근무 예정** |
| 실제 근무 중 | **근무 중** |
| 매칭 종료 후 다른 수급자 연결 대기 | **재매칭 대기** |
| 근로관계 종료 | **근로 종료** |

기존에 만든 ‘올해 계약이면 유효함’은 **올해 계약인지 구분하는 정보**로 유지하고, 근무 상태와 따로 보여주는 것이 좋습니다. 예를 들어 `2026년 계약 · 매칭 대기`처럼 표시할 수 있습니다.

**수급자별로 조건을 연결하겠습니다.**

근로자 한 명이 여러 수급자를 담당할 가능성을 고려하면, 아래처럼 구성하는 편이 자연스럽습니다.

| 수급자 | 적용 기간 | 시급 | 근무 일정 | 상태 |
|---|---|---:|---|---|
| 김○○ | 20261001~20261231 | 14,000원 | 월·수·금, 09:00~12:00 | 근무 중 |
| 박○○ | 20261101~20261231 | 15,000원 | 화·목, 13:00~16:00 | 근무 예정 |

보험 판단에 사용할 월별 시간은 이 근로자의 **기관 내 근무 전체를 확인할 수 있어야** 합니다. 수급자 한 명의 시간만 보고 계산하면 누락될 수 있습니다. 예정 시간과 실제 근무 시간도 구분해 보관하겠습니다.

**‘오탈자 수정’과 ‘조건 변경’은 다른 작업으로 만들겠습니다.**

- **오탈자 수정:** 잘못 입력한 내용을 바로잡고 수정 이력을 남깁니다.
- **조건 변경:** 이전 조건을 보존하고, 새 조건의 적용 시작일을 등록합니다.
- **계약 갱신:** 새 계약을 작성하면서 이전 정보를 가져옵니다.

예를 들어 10월 15일부터 시급이 오르면 다음처럼 기록합니다.

| 적용 기간 | 시급 | 변경 사유 |
|---|---:|---|
| 10월 1일~14일 | 14,000원 | 기존 조건 |
| 10월 15일부터 | 15,000원 | 돌봄 난이도 증가 |

이렇게 해야 10월 급여를 확인할 때 변경 전후 조건을 설명할 수 있습니다. 기간이 정해진 임시 변경이면 종료 후 어떤 조건으로 돌아가는지도 명확해야 합니다.

**구두로 변경한 상황도 기록하되, 문서 확인 상태를 함께 두겠습니다.**

현장에서 먼저 합의한 사실을 기록할 수 있어야 합니다. 다만 임금·소정근로시간 등의 변경에는 서면 명시·교부 의무가 관련되므로, ‘구두 변경으로 모든 절차가 끝났다’고 시스템이 처리하는 것은 피해야 합니다. [근로기준법 제17조](https://www.law.go.kr/법령/근로기준법/제17조)

변경 화면에는 다음을 받는 것이 좋겠습니다.

- 변경 전후 금액·시간
- 적용 시작일과 필요 시 종료일
- 변경 사유
- 근로자와 합의한 날짜
- 확인 문서 또는 **문서 확인 필요** 상태

사용자는 상세 화면에서 **수급자 연결 → 근무 조건 입력 → 조건 변경** 순서로 작업하고, 보험은 별도의 **월별 보험 확인**에서 처리하게 하겠습니다. 모든 내용을 계약 등록 화면에서 한꺼번에 요구하면 사용 부담이 큽니다.

우선 두 가지를 확인하고 싶습니다.

1. 한 근로자가 **여러 수급자를 동시에 담당하며, 수급자마다 시급이 다를 수 있나요?**
2. 말씀하신 **59.5시간은 월별 예정 근무시간인가요, 실제 근무한 시간을 합산한 값인가요?**

이 두 가지가 정해지면 계약 조건 화면과 월별 보험 확인 화면의 구조를 구체화할 수 있습니다.
