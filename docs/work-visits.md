# 라운딩 관리 — 월간 달력 대시보드

메인 메뉴 **센터 실무 → 라운딩**에서 확인한다.

## 대상자와 담당자

- 방문요양 서비스 관리에서 해당 월의 ‘이 달의 수급자’를 체크하고 **선택 적용**한 명단만 가져온다. 계약 기간, 과거 할일, 서비스 정지 기록을 근거로 대상을 추가하지 않는다.
- 월별 선택에서 해제하면 라운딩 대시보드에서도 제외된다. 기존 계획·방문·할일 기록 자체는 삭제하지 않는다.
- **모두 / 박준규 / 황영상** 탭은 달력·현황 숫자·완료 및 남은 명단을 함께 필터링한다. 담당 미지정은 ‘모두’에 표시한다. 검색 조건도 함께 적용한다.
- 대상, 방문 완료, 남은 대상, 방문 계획, 미계획, 보류를 표시한다. 남은 대상은 대상에서 완료 인원을 뺀 값이며 보류·취소 대상도 포함한다. 방문 계획과 미계획 숫자에서는 보류 대상을 분리한다.

## 하나의 월간 달력

- RFID 확인의 달력 및 상세 패널 스타일을 재사용한다. 날짜 하나에 여러 수급자의 이름을 표시하고, 보라색 계획과 초록색 실제 방문을 구분한다.
- 셀에 세 건까지 표시하고 나머지는 ‘외 N건’으로 표시한다. 날짜를 누르면 해당 날짜의 모든 방문 계획·실제 방문을 확인할 수 있다.
- 아래 **방문 완료 / 남은 대상** 명단은 날짜 선택과 무관하게 이번 달의 수급자 전체를 보여준다. 수급자를 선택하면 담당자·방문일을 입력하는 상세 패널이 열린다. PC·모바일 모두 상세 패널을 화면 안에 고정해, 날짜 선택 후 명단을 보러 페이지 아래로 이동하지 않아도 된다. 긴 내용은 패널 안에서 스크롤한다.
- 날짜 상세의 **방문계획 수급자 추가**를 누르면 남은 대상을 검색 가능한 목록 버튼으로 표시한다. 클릭하면 선택한 날짜의 계획으로 즉시 저장하며, 저장 후 같은 날짜의 대상은 추가 목록에서 빠진다. 완료 대상은 제외하고 보류·취소 대상은 추가할 수 없게 표시한다. 담당 미지정 대상은 목록 위에서 사회복지사를 선택한다. 다른 날짜의 계획이 있으면 날짜 변경임을 표시한다.
- 빠른 추가와 수급자 상세에서 선택 항목인 계획 시작·종료 시각을 입력할 수 있다. 두 시각을 모두 비우면 시간 미정이며, 입력 시 종료는 시작보다 늦어야 한다. 계획 시간대는 달력·방문 명단에 표시하고 실제 방문 완료와 구분해 보존한다. 기존 클라이언트가 시간 필드를 생략해 저장해도 기존 시간대를 지우지 않는다.
- **방문 계획 저장**은 방문요양 서비스 관리와 같은 라운딩 기록을 수정한다. **실제 방문 완료**는 확인 후 기존 연결 할일을 완료하고 수행 기록도 저장한다. 미래 날짜는 계획으로만 저장한다.
- 기존 업무 계획·실제 수행 날짜도 연결 태스크 기준으로 달력에 반영한다. 완료 상태만 있고 방문일이 없는 과거 기록은 완료 명단에 남기되 임의의 방문일을 만들지 않는다.
- `recipient_service_rounding.payload.plannedDate`에 계획일을 보존한다. 실제 방문일이 달라져도 기존 계획일을 덮어쓰지 않는다. 별도 스키마 변경 없이 JSON payload에 저장하며 기존 계획은 `date`를 계획일로 해석한다.

## 서비스 일시정지와 복귀

현재 월의 대상자를 선택한 상세 패널에서 **서비스 일시정지**와 **복귀 처리**를 제공한다. 정지·복귀는 기존 서비스 상태 및 연결 할일에 반영한다.

- 정지 사유는 필수이며 미래 정지일·복귀일 및 정지일 이전 복귀를 차단한다.
- 정지 중인 미완료 할일은 보류한다. 완료 기록은 보존하며 예정 복귀일이 되어도 자동 복귀하지 않는다.
- 같은 달 실제 복귀 시 기존 미완료 할일의 보류를 해제한다. 이전 달의 보류는 자동 이월하지 않는다.
- 과거 월에서도 서비스의 현재 정지 상태가 보이므로 과거 시점의 서비스 상태 집계로 해석하지 않는다.

## API와 검증

- 조회: `GET /api/work/visits/YYYY-MM`. 월별 선택 명단과 `rounding`, `plannedDates`, `visitedDates`, 서비스 상태 및 연결 할일을 반환한다.
- 계획·실제 방문 저장: `PUT /api/work/service-rounding?month=YYYY-MM`. 버전 충돌 검사와 할일·수행 기록 연동은 기존 트랜잭션을 사용한다.
- 기존 `POST /api/work/visits/YYYY-MM`도 월별 선택 명단 포함 여부를 검사한다.
- `node --test tests/work-visits.test.mjs tests/recipient-service-months.test.mjs`: 월별 대상 제외, 계획일·실제 방문일 분리, 완료 연동, 버전·중복 검증, 정지·복귀 및 완료 우회 차단을 검증한다. PostgreSQL 어댑터는 SQLite SQL 브리지로 검증한다.
- `tests/work-visits-ui.mjs`: 임시 SQLite API와 실제 앱 메뉴를 사용해 PC·모바일에서 단일 달력, 담당자 필터, 대상 제외, 계획 변경, 실제 방문 완료, 서비스 관리 연동 및 가로 넘침 여부를 확인한다.
