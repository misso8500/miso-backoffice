# 라운딩 관리 — 명단·할일 연결과 일시정지·복귀

## 1차: 명단에서 할일 생성·완료

메인 메뉴 **센터 실무 → 센터업무(할일) → 라운딩**에서 확인한다.

1. 조회 월을 고른다.
2. 해당 월과 계약·서비스 기간이 겹치는 수급자 명단을 확인한다.
3. 서비스 제공 및 일시정지 여부를 실무자가 확인한 뒤 박준규·황영상 중 라운딩 담당자를 선택한다.
4. **확인 후 라운딩 할일 생성**을 누른다. 해당 월 말일을 기한으로 수급자가 연결된 센터 할일이 생성된다.
5. 라운딩 후 명단의 **라운딩 완료**, 또는 기존 할일 화면의 완료 기능으로 처리한다.
6. 명단을 다시 불러오면 같은 태스크의 완료·재개·취소 상태를 확인할 수 있다. 라운딩 명단에서 할일 화면으로 돌아갈 때 기존 할일 목록도 새로 불러온다.

같은 달·같은 수급자에 대한 재요청은 기존 태스크를 반환한다. 완료·취소된 태스크도 조용히 새로 만들지 않는다. 다음 달 업무는 미리 생성하지 않는다. 과거 월 조회와 미처리 업무 확인은 허용한다.

## 2차: 일시정지 → 보류 → 복귀 → 재개

현재 월의 수급자 행에서 **서비스 일시정지**를 눌러 정지 시작일·사유·복귀 예정일을 입력한다. 예정일은 미정이면 비워둔다.

- 정지일은 서비스 시작일 이전이나 미래일로 입력할 수 없고, 사유는 필수다. 기존 정지·복귀 이력과 겹치는 정지를 차단한다.
- 정지 시작 월부터 미완료 라운딩을 보류한다. 이미 완료·취소한 할일은 바꾸지 않고 과거 월의 미처리도 소급 보류하지 않는다.
- 정지 중에는 라운딩 할일 생성과 연결 태스크의 완료·재개·수정, 새 계획·새 수행 등록을 서버에서도 차단한다. 기존 계획·수행 기록은 삭제하지 않는다. 기존 기록의 정정과 할일 취소는 별개다.
- 복귀 예정·예정일 경과·복귀일 미정을 표시한다. 예정일이 되어도 자동 복귀하지 않는다.
- **복귀 처리 → 실제 복귀일 → 복귀 확정**으로 처리한다. 미래 복귀일이나 정지일 이전 날짜는 허용하지 않는다.
- 같은 달 복귀 시 기존 미완료 할일의 보류를 해제한다. 할일 ID·담당자·기한을 유지하고 새 할일은 만들지 않는다. 완료한 할일도 재생성하지 않는다.
- 실제 복귀월보다 앞선 달의 보류는 자동 이월·완료하지 않고 ‘이전 달 보류 기록 · 확인 필요’로 남긴다. 복귀월 및 이후의 기존 보류만 해제한다. 다음 달의 할일 자동 생성은 별도 개발 단위다.
- 서비스 상태 변경 입력은 현재 월에서 제공한다. 과거 조회 화면에도 서비스의 **현재** 정지 상태와 최근 복귀 기록이 표시되므로 과거 시점의 서비스 상태 집계로 사용하지 않는다.
- 정지·복귀와 태스크 상태 변경은 트랜잭션으로 처리하고 실제 로그인 수정자를 이력에 남긴다. 동시에 복귀 처리하거나 중복 정지 등록하면 최신 상태를 확인하도록 충돌을 반환한다.

## 명단과 표시 기준

- 임시등록은 제외한다. 실제 날짜 형식의 계약 등록일·계약 만료일·서비스 시작일·서비스 종료일이 모두 있어야 하며 네 기간의 실제 교집합이 조회 월에 존재해야 한다.
- 숫자는 **계약기간 기준 명단**이며 실제 서비스 이용 중 인원을 확정 집계하는 화면이 아니다. 일시정지·복귀는 이 화면에 등록한 기록을 기준으로 하며 기존 데이터에서 임의 추정하지 않는다.
- 종료 상태의 수급자도 기간이 겹치거나 연결된 라운딩업무가 있으면 표시하되, 새 업무 생성은 차단하고 상태 확인을 안내한다.
- 연결된 업무 또는 현재 정지 기록은 이후 계약기간이 수정되더라도 명단에서 보존하고 ‘종료·기간 변경 확인 필요’를 표시한다.
- 미완료 라운딩 및 생성 전 명단은 평소에도 표시한다. 현재 월은 말일까지 남은 날짜가 7일 이하이면 경고하며, 지난달의 미처리도 경고한다.
- 필터는 전체 / 할일 생성 전 / 미완료 / 일시정지·보류 / 완료 / 취소됨, 이름 검색을 제공한다. 현재 정지 중인 대상과 보류 태스크는 미완료 경고에서 분리한다. 서비스 정지 상태와 할일 완료 상태는 별개이므로 완료 인원과 정지 인원은 겹칠 수 있다.
- 완료 체크와 실제 수행 기록은 기존 센터업무와 동일하게 별개다. 이번 라운딩 완료 기준은 연결 태스크 완료다.

## 이번에 포함하지 않은 다음 단위

- 월별 담당자 저장 및 서비스 상태에 따른 자동 라운딩 생성.
- 담당자 변경 시 인수인계 생성·미완료 이관·새 라운딩 생성. 현재 명단에는 담당자 변경 기능을 제공하지 않는다. 기존 할일에서 담당자만 바꿔도 인수인계나 새 라운딩이 자동 생성되지는 않는다.
- 종료 후 남은 업무의 사유를 남긴 수동 제외. 기존 할일 취소는 ‘라운딩 완료’나 ‘대상 제외’로 집계하지 않는다.
- 라운딩 예정일 기반의 라운딩 예정 / 미수행 구분.
- 서비스 신규·유지·중단·종료에 대한 월별 실인원 집계 및 지난달 비교.

위 항목은 [서비스 기능표](<service design/센터운영-서비스-기능표.md>)의 확정 기준에 따라 다음 단위로 연결한다.

## 저장·배포

- API: 인증된 `GET /api/work/visits/YYYY-MM`, `POST /api/work/visits/YYYY-MM`.
- 정지·복귀 API: 인증된 `POST /api/work/recipient-services/:recipientId/pause`, `POST /api/work/recipient-services/:recipientId/resume`. 복귀 요청에는 `pauseId`·`version`·`returnedDate`가 필요하다.
- 생성 요청: `recipientId`, `assigneeId`, `serviceConfirmed: true`. 서버에서 대상·기간·담당자와 현재 상태를 다시 검증한다.
- `work_visit_tasks`가 월·수급자와 기존 태스크를 연결한다. 기본 단위는 `(month, recipient_id)`로 유일하며 PostgreSQL에서는 대상 행을 잠근 후 생성한다.
- 기존 `work_tasks`와 생성 이벤트를 한 트랜잭션으로 기록한다. 실제 로그인 계정을 작성자로 남긴다.
- 추가 테이블: `recipient_service_pauses`, `work_visit_holds`, `recipient_service_pause_events`. 기존 계약·서비스 기간을 덮어쓰지 않는다. 보류 여부는 연결 테이블로 계산하며 기존 태스크의 상태 제약을 변경하지 않는다.
- SQLite 시작 시 및 PostgreSQL 스키마에 새 테이블을 추가한다. PostgreSQL의 RLS와 anon/authenticated 직접 접근 차단을 포함한다. 운영 반영에는 API 서버 재시작·배포가 필요하다.

## 검증

- `node --test tests/work-visits.test.mjs`: 날짜 교집합, 대상 검증, 중복 방지, 월말 경고, 정지·복귀, 완료·계획 수행·수동 수행 우회 차단, 실제 수정자 이력, 같은 태스크 재개, 완료 태스크 보존, 다른 달 복귀의 과거 보류 유지.
- PostgreSQL 어댑터 검증은 SQLite 기반 SQL 브리지로 수행하며 운영 PostgreSQL 접속 검증은 아니다. 동시 재요청 테스트는 SQLite에서 수행한다.
- `tests/work-visits-ui.mjs`: 실제 임시 SQLite API와 브라우저를 연결하여 1400px·390px에서 생성·완료 연동, 정지·복귀, 미정·경과 알림, 일반 할일 완료 차단, 같은 태스크 재개와 완료 기록 보존을 확인한다. 운영 DB는 사용하지 않는다.
- 기존 할일·계획/수행·반복업무·근무기록 회귀 테스트와 프로덕션 빌드를 확인한다.
