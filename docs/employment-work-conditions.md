# 수급자별 근로계약 조건

## 이번 개발 범위

근로계약에 수급자별 매칭·근무 조건과 지급 약정을 저장한다. 실제 급여, 근무 실적, 차량동행 실적, 보험료 계산·신고는 이번 범위에 포함하지 않는다.

## 사용 방법

1. 근로계약 등록에서 근로자 정보와 계약 기간을 입력한다.
2. 수급자별 조건 카드에 수급자, 서비스 형태, 가족요양 여부, 매칭 상태를 입력한다. 매칭 전이라면 수급자 미지정과 매칭 대기로 보관할 수 있다.
3. 조건 적용 기간, 요일·시간·휴게, 월 약정 최대 시간, 시급 또는 월급을 입력한다. 59.5는 해당 수급자에 대한 월 약정 상한이며 실제 근무시간이나 급여 계산값이 아니다.
4. 해당 수급자에게만 적용할 차량동행 1회 약정액을 입력한다. 약정이 없으면 0원이다. 실제 수행 횟수는 입력하지 않는다.
5. 근로자 공통 월정액 교통비를 한 번 입력한다. 지급 시 만근 대비 인정 근무 횟수로 비례한다는 약정만 보관하며 이번 화면에서는 계산하지 않는다.
6. 문서 확인 상태와 변경·합의 메모를 확인하고 저장한다.

수급자 추가는 조건 추가로 처리한다. 같은 수급자의 실제 조건 변경은 이전 조건 적용 종료일을 조정하고 새 기간의 조건을 추가한다. 같은 수급자의 조건 기간은 겹칠 수 없다. 오탈자는 계약 수정으로 바로잡을 수 있으며, 새 방식의 조건 수정 전 내용은 서버에서 자동 보관한다.

서비스 일시정지·종료에는 적용일을 입력한다. 해당 적용일부터 현재 매칭 수에서 제외된다. 미래에 적용할 중단이라면 그 전까지는 현재 매칭으로 표시된다. 재개 시에는 이전 기록을 확인하고 적용 기간·상태를 수정한다. 수정 전 값은 이력에서 확인한다. 이는 실제 근무 실적을 계산하는 기능이 아니다.

## 표시 기준

- 올해 계약 기간과 겹치는지는 기존 연도 기준으로 확인한다.
- 새 조건이 등록된 계약은 현재 매칭이 없으면 매칭 대기·근무 예정·일시정지·종료 등으로 표시하고 현재 유효 목록에서 제외한다. 법적 계약 무효 판단을 뜻하지 않는다.
- 두 명 이상 현재 매칭되면 합산 근무시간·보험 가입 검토 안내를 표시한다. 수급자 수만으로 60시간 이상이나 보험 가입을 확정하지 않는다.
- 일시정지·종료 조건이 있으면 보험 변경 검토를 안내한다. 보험별 실제 적용은 별도 확인한다.
- 기존 계약은 매칭 정보 확인 필요로 표시하고 기존 유효성 판정을 유지한다. 오탈자 수정은 기존 임금·수당만으로 저장할 수 있다. 수급자별 조건 등록을 누르면 새 방식으로 전환한다.
- 갱신계약은 기존 금액·조건을 가져오되 기간은 공란, 매칭·문서 상태는 확인 전 상태로 시작한다.

## 저장 구조와 호환성

`employment_contracts.work_conditions`에 월정액 교통비, 조건별 추가 정보, 수정 전 기록을 저장한다. Postgres는 JSONB, SQLite는 JSON 문자열이다. 기존 `contractTerms`는 임금·기존 수당 저장에 그대로 사용하고 조건의 `termId`로 연결한다. 수급자 연결은 기존 관계 테이블에도 반영한다.

Postgres의 새 열은 `server/postgres/schema.sql`에 포함되어 있다. 대상 DB를 확인하고 `npm run supabase:init`으로 적용하거나 API를 재시작하면 시작 시 적용된다. SQLite는 시작 시 열을 추가한다. 기존 레코드는 새 열이 비어 있는 상태로 유지되어 자동으로 매칭 대기로 바뀌지 않는다. 기존 CSV 형식도 그대로 읽는다. CSV로 가져온 계약은 기존 계약과 같이 추가 정보 확인 후 전환한다.

계약 본문·조건·연결 정보는 한 트랜잭션으로 저장해 일부 저장 실패 시 원복한다. 다른 사용자가 먼저 수정한 오래된 계약을 덮어쓰려 하면 409 오류로 막는다. 최신 계약을 다시 조회해 수정해야 한다.

`history`는 클라이언트 입력을 신뢰하지 않고 서버가 생성한다. 조건 추가 정보·약정 금액·임금이 바뀌면 직전 값과 수정 시각을 보관한다. 전체 개인정보 변경 이력이나 전자서명 증빙을 대신하지 않는다. 기존 형식의 계약은 새 조건으로 전환한 이후부터 해당 기록이 생긴다.

## 코드 및 검증

- `src/EmploymentConditionsEditor.tsx`: 계약 입력·수정 카드
- `src/EmploymentConditionsDetails.tsx`: 상세 표시와 수정 전 기록
- `src/lib/employment-contracts.ts`: 현재 매칭·유효 상태 표시
- `server/work-conditions.mjs`: 공통 검증·기록 생성
- `server/postgres/api.mjs`, `server/api.mjs`: 조회·저장·트랜잭션
- `tests/work-conditions.test.mjs`: 입력 검증·약정 구분·매칭·기록 테스트
- `tests/work-conditions-api.test.mjs`: 임시 SQLite DB와 가짜 인증 서버를 사용하는 실제 HTTP 저장·조회·수정·원복·충돌 테스트

```bash
node --test tests/*.test.mjs
npm run build
```

실제 운영 PostgreSQL·Google 계정으로의 수동 점검은 별도다. 실제 계정으로 로그인하여 매칭 전 보관, 수급자 두 명의 서로 다른 약정 저장, 중단 적용일 표시, 수정 이력 확인, 기존 계약 오탈자 수정, 새로고침 후 값 유지 여부를 확인한다.
