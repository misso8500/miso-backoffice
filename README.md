# Miso Backoffice Lite ERP System

## Version

현재 이 프로젝트는 `v1.0 MVP`를 목표로 개발한다.

`v1.0 MVP`는 미소 노인재가복지센터 운영 업무 전체를 완성하는 최종 버전이 아니라, 가장 먼저 필요한 `수급자 관리 흐름`을 실제로 사용할 수 있는 수준까지 정리하는 첫 제품 버전이다.

## Development Setup

현재 MVP는 `learning-wiki` 레퍼런스와 같은 로컬 우선 구조를 사용한다.

```text
Browser
  -> Vite dev server: http://127.0.0.1:5173
  -> /api proxy
  -> Node API server: http://127.0.0.1:5174
  -> SQLite: data/miso-backoffice.sqlite
```

주요 기술은 다음과 같다.

- React, TypeScript, Vite
- Node.js `http`, `node:sqlite`
- SQLite
- `lucide-react`

`node:sqlite`를 사용하므로 Node.js 24 이상을 기준으로 한다.

최초 설치:

```bash
npm ci
```

로컬 실행은 터미널 두 개를 사용한다.

터미널 1:

```bash
npm run api
```

터미널 2:

```bash
npm run dev
```

DB 파일 경로는 다음 순서로 결정된다.

1. 환경 변수 `MISO_BACKOFFICE_DB_PATH`
2. 프로젝트 루트의 `miso-backoffice.local.json`
3. 기본값 `data/miso-backoffice.sqlite`

개인정보가 포함될 수 있으므로 실제 DB 파일과 개인별 설정 파일은 Git에 커밋하지 않는다. 로컬 SQLite 구조는 단일 사용자 MVP 검증을 위한 기반이며, 여러 사용자의 동시 접속이 필요해지면 인증과 서버형 데이터베이스 구조를 별도로 도입한다.

## Product Definition

Miso Backoffice는 미소 노인재가복지센터의 장기요양 운영 업무 중, 먼저 `수급자 관리`를 안정적으로 정리하기 위한 백오피스 시스템이다.

이 프로젝트의 첫 번째 목표는 모든 업무를 한 번에 통합하는 것이 아니라, 흩어진 수급자 정보를 한 곳에서 관리하고 계약 및 라운딩 이력을 지속적으로 추적할 수 있는 `v1.0 MVP`를 만드는 것이다.

즉, 현재 README에서 정의하는 제품 범위는 `최종 ERP 전체 범위`가 아니라 `v1.0 MVP 범위`를 기준으로 한다.

## Problem

현재 수급자 관리 업무에는 다음과 같은 문제가 있다.

1. 수급자의 기본 정보가 여러 곳에 흩어져 있어 확인과 수정이 비효율적이다.
2. 계약 기간, 갱신 시점, 확인 필요 상태를 한눈에 파악하기 어렵다.
3. 월간 라운딩 업무에서 어떤 변화가 있었는지 연속적으로 추적하기 어렵다.
4. 데이터가 누적되더라도 다음에 무엇을 확인해야 하는지 시스템이 알려주지 못한다.

## v1.0 MVP Goal

`v1.0 MVP`의 1차 목표는 `수급자 관리 흐름 1개를 끝까지 연결하는 것`이다.

즉, 아래 질문에 시스템이 답할 수 있어야 한다.

- 현재 등록된 수급자는 누구인가
- 각 수급자의 계약 상태는 어떤가
- 최근 라운딩 기록은 무엇인가
- 지금 확인이 필요한 수급자는 누구인가

## Target User

- 센터 운영자
- 수급자 정보와 계약 상태를 관리하는 실무자
- 월간 라운딩 기록을 확인하거나 입력하는 담당자

## v1.0 MVP Scope

이번 `v1.0 MVP`에 포함하는 범위는 아래와 같다.

1. 수급자 기본 정보 등록, 수정, 조회, 목록 확인
2. 계약 시작일, 종료일, 주요 상태값 관리
3. 갱신 예정 또는 확인 필요 상태 표시
4. 월간 라운딩 기록의 최소 단위 입력 및 조회
5. 수급자별 이력 흐름 확인

## v1.0 MVP Out of Scope

아래 항목은 현재 `v1.0 MVP` 범위에서 제외한다.

- 요양보호사 급여 계산
- 급여 명세서 자동 생성
- 퇴직금 적립 계산
- 복잡한 통계 대시보드
- 외부 알림 및 메시지 연동
- 고도화된 권한 체계

## Product Principles

이 프로젝트는 아래 원칙에 따라 개발한다.

1. 한 번에 넓게 만들지 않고, 수급자 관리 1축을 먼저 완성한다.
2. 화면보다 데이터 구조와 상태 추적 가능성을 우선한다.
3. 모든 기능은 티켓 단위로 쪼개고 완료 기준을 먼저 작성한다.
4. `Done`은 구현만이 아니라 검증과 학습기록까지 포함한다.
5. 반복되는 판단은 문서와 운영 규칙으로 승격한다.

## v1.0 MVP Success Criteria

아래 조건을 만족하면 `v1.0 MVP`가 작동한다고 판단한다.

- 실무자가 수급자를 새로 등록할 수 있다.
- 등록된 수급자 목록을 확인하고 개별 정보를 수정할 수 있다.
- 계약 만료 또는 갱신 확인이 필요한 대상을 구분할 수 있다.
- 수급자별 라운딩 기록을 남기고 다시 조회할 수 있다.
- 다음 구현 티켓으로 연결할 수 있을 만큼 데이터 구조와 문서 구조가 정리되어 있다.
